# P0b 可达性与登录实测 —— 操作手册

> 这是本项目**唯一的存亡关口**。P0a 已证明"我们这边没有自动化特征"；P0b 要回答的是
> **平台会不会因此针对我们**。这个答案只能靠一次真实、完全人工的使用来取得。

## 零、先跑自检（10 秒，不联网）

```powershell
pwsh -File tools\run-p0b-reachability.ps1 -SelfTest
```

自检会在**本进程内**起一个 mock 服务器（标题为"请完成安全验证"的页面 + 模拟 403/429 响应），
验证采集链路是否正常：导航事件、挑战关键词命中、HTTP 异常状态码记录、报告落盘。

预期：退出码 0，`summary.challengesDetected = 1`、`summary.httpErrors = 2`、
`summary.signal = blocking-signal-observed`。若不符，先修工具再跑真实实测。

## 一、这一步在验证什么

| 要回答的问题 | 为什么只能实测 |
|---|---|
| Electron 客户端能否正常加载目标平台 | 站点策略不在我们控制内 |
| 能否正常登录、会话是否保持 | 登录风控与设备/环境绑定策略未知 |
| 是否弹出人机验证 / "环境异常"提示 | 风控策略是黑盒 |
| 是否返回 403 / 429 等异常状态码 | 同上 |
| 是否接入第三方人机验证服务 | 通过请求域可观测 |

## 怎么做（全部手动，约 5 分钟）

```powershell
pwsh -File tools\run-p0b-reachability.ps1
```

带自定义地址或输出路径：

```powershell
pwsh -File tools\run-p0b-reachability.ps1 -Url "https://chat.deepseek.com/" -Out "docs\audits\2026-10-02-p0b-reachability-raw.json"
```

窗口打开后：

1. **用你平时的方式登录**（扫码 / 验证码 / 密码都行）。
2. **随便问一句话**，确认能正常对话。
3. **若出现人机验证或"环境异常"提示**：
   - **不要试图绕过**（本项目明令禁止绕过验证）；
   - 截图，并记下提示原文；
   - 直接关闭窗口即可，报告会记录命中信号。
4. **结束时直接关闭窗口** —— 报告自动落盘。

## 工具做了什么、没做什么

**做了什么（只读采集）**：
- 记录导航、加载失败、渲染进程崩溃、HTTP 4xx/5xx 状态码；
- 按关键词检测页面上是否出现验证/风控提示文案（只读 `innerText`）；
- 记录第三方请求域（用于判断是否接入人机验证服务）；
- 记录 Cookie 的**名字与长度**（不记值）、当前 UA；
- 记录会话分区名与本地用户目录位置。

**明确没做**：
- ❌ 不向页面写入任何内容（不注入脚本到页面世界、不改 DOM、不派发合成事件）；
- ❌ 不使用 CDP / 远程调试，不引入 Selenium / Puppeteer / Playwright；
- ❌ 不代填表单、不点按钮、不模拟回车、不代写剪贴板；
- ❌ **不绕过任何验证**——出现验证就停手并记录。

## 隐私处理

- URL 写入报告前**丢弃 query**（只留 `origin + path`），避免把会话参数写进仓库；
- Cookie **只记名字与长度**，不记值；
- 报告位于 `docs/audits/`，提交前请自行过一眼是否含敏感内容。

## 怎么判定结果

报告里的 `summary.signal` 只是**提示**，不是结论。请结合你的实际观察判断：

| 观察 | 含义 | 后续 |
|---|---|---|
| 正常登录、正常对话、无任何提示；`challengesDetected = 0` | **通过** | 进入 P1 Gate，再开始 P2 外壳开发 |
| 出现验证码但**一次即可通过**，之后正常 | 边界情况 | 记录发生频率；观察后续是否复现 |
| 出现"环境异常"/"访问受限"，或反复要求验证 | **不通过** | 触发 ADR-0001 的**战略备选**：改用"本机 Chrome 直启"路线 |
| 出现 403 / 429，或登录被拒 | **不通过** | 同上 |

## 报告字段速查

| 字段 | 含义 |
|---|---|
| `summary.challengesDetected` | 命中的验证/风控提示次数 |
| `summary.signal` | `no-blocking-signal-observed` 或 `blocking-signal-observed`（提示值） |
| `challenges[]` | 每次命中的时间、URL、关键词、上下文摘录 |
| `responsesWithErrorStatus[]` | 4xx/5xx 响应（含状态码与 URL） |
| `thirdPartyHosts[]` | 非目标域的请求域（判断是否接入外部验证服务） |
| `sessionFacts` | Cookie 名与长度、UA、最终 URL |
| `events[]` | 全量事件时间线（导航、加载、崩溃等） |

## 注意

- 运行前**不要**把 `ELECTRON_RUN_AS_NODE` 留在环境里（脚本会自行清除）。
- 这一步会真实访问目标平台，属于**有平台暴露**的操作——这也是它必须由你亲自执行的原因。
- **必须在普通 PowerShell 里运行，不要在 AI 助手的执行沙箱内运行**：沙箱会限制子进程的对外网络，
  表现为页面永远加载不出来（这不是工具缺陷；自检模式不联网，因此在沙箱内也能通过）。
- 若窗口里页面一直空白：检查本机代理是否正常（目标站点需经你的代理访问）。

## 工具自身的已验证范围（诚实声明）

| 已验证 | 方式 |
|---|---|
| 事件采集（导航 / 加载完成 / 加载失败） | 自检 + `about:blank` 实测 |
| 挑战关键词命中（含中文风控文案） | 自检（mock 页面命中 4 个关键词） |
| HTTP 403 / 429 异常状态码记录 | 自检（mock 返回 403 与 429，均被捕获） |
| 增量实时落盘（强杀不丢证据） | 用 `about:blank` 与自检各验证一次 |
| 报告结构与字段 | 自检报告逐字段核对 |

| 未验证（只能由你这次实操覆盖） | 原因 |
|---|---|
| 真实站点加载与登录流程 | 需要你的账号与交互 |
| 平台是否真的拦截 | 这正是本次要回答的问题 |
| 第三方域清单 | 需真实页面的请求才能采集 |

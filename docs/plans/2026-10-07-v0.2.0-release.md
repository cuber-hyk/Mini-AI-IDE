# v0.2.0 发布准备与验证

用户要求当前UI阶段完成后提交、合并、发布，授权版本由代理判断。本次从0.1.2升至0.2.0，包含工作区导航、主题、文件全屏/恢复、审阅标签与此前尚未发布的工具/自动继续能力。Diff列表和记录机制重做、多项目并行不在本次实现范围，保留独立议题。

## 步骤与验证

1. 核查Git差异、发布范围、未决项，更新版本与CHANGELOG。
2. 构建、完整测试、离线原生自检与工作区验收；不将本地夹具当作真实官网自动发送验收。
3. 完整构建NSIS、Portable、latest.yml和blockmap，验证哈希、包内版本、源码与编译结果；打包程序隔离自检。
4. 展示最终status/diff与产物，按用户在审阅实际UI后的本次明确授权提交/合并；不直接git push。
5. 发布必须指向与包内源码一致的远端提交；远端源码同步方式确认前不公开Release。发布附件校验后再设为latest，不更新旧版Release附件。

# Mini-AI-IDE PoC 计划（Windows / DeepSeek 网页版）

## 目标

一句话：**在 Windows 上做出一个桌面工具——左侧 Monaco 编辑本地文件，右侧用独立 `WebContentsView` 加载 DeepSeek 网页版；程序对网页只读不写：读取模型回复、解析代码围栏、diff 预览、经用户确认后写回本地文件（可撤销）。出程（复制代码、粘贴、写提示词、发送）全部由用户手动完成。并实测确认整个链路"没有自动化特征、平台不把我们的客户端当成程序"。**

**目标边界（关键）**：目标是**抹掉"自动化特征"，不是抹掉"Electron 身份"**。平台知道我们是 Electron 应用没关系，只要不判定为"程序在操作"即可。因此本项目**不伪装 Chrome、不对抗指纹识别**。

**人机分工（关键）**：程序**不向网页写入任何内容**。程序只做两件事：只读取回复、只把解析结果写到本地文件（经用户确认）。**提示词由用户自己写，代码由用户自己复制粘贴，发送由用户自己点。**

非目标（本计划不做）：跨平台、文件/图片上传、**任何形式的向网页写入**（键盘注入、剪贴板代写、DOM 修改、模拟发送）、多标签与多账户、全仓库索引、批量操作、商业分发；**patch Chromium 构建；任何形式的指纹伪装**。

## 范围

**在范围内**：无自动化特征核验；平台可达性与登录实测；Electron 外壳与进程边界；Monaco 编辑器 + 主进程文件读取（编码、大小、路径白名单）；回程只读采集、解析、diff 预览与一键应用；会话分区与登录态持久化。

**范围外**：任何逆向 API 或协议伪造；**任何指纹伪装或 Chrome 身份模拟**（随机化/伪装宿主属性、改 UA 冒充 Chrome）；patch Chromium 构建；Playwright/Selenium 驱动；**任何向网页写入的手段**（`SendInput`、`sendInputEvent`、DOM 赋值、合成事件、模拟回车/点击、代写剪贴板）；网络请求经 Node 代理；**把解析结果自动回注给模型的自动循环**。

## 事实来源

- `IDE接入网页版AI.md` — 需求来源。**其"风控规避要求"一节属于理想化需求，已被 ADR-0001 修正；凡与本计划冲突处以本计划为准。**
- `docs/adr/*.md` — 已接受的架构决策。
- 可行性旁证：Obsidian 核心插件 Web viewer（基于 Chromium webview 标签）实测可正常加载并登录 `chat.deepseek.com`，说明该站点**未禁止 Electron 客户端嵌入**。该旁证的强度仅限于此：它证明"能打开页面"，**不证明**平台不对该客户端做区分对待，也不涉及任何网页写入行为。本项目与 Obsidian 的差别在于"程序读取页面"——读取不产生输入特征，因此旁证的适用范围比"程序写入页面"更贴合。
- 仓库基线：`master`，提交 `ec4ab55`（init + 需求文档）。
- 本机工具链：Node `v22.19.0`、pnpm、npm、git 均可用。
- **待填充**：自动化特征检测工具的具体版本与输出格式（P0a 内确定并固定）。

## 风险

> **本表只列封号 / 账号风险**（用户定义的唯一关心项）。工具本身的维护性、体验与合规问题另见下方"非封号项"。

| 风险 | 等级 | 应对 |
|---|---|---|
| 平台把"Electron 客户端"整体视为高风险来源 | **中低**（原中高，已由实测下调） | P0b 基线实测：**未**出现针对性拦截（无验证码、无 4xx/5xx、登录与对话正常）；唯一出现的「使用环境异常」警告已由受控实验定位为 **UA 自报标记**，且移除后消失。残留风险：平台若整体针对 Electron 客户端，只能切"本机 Chrome 直启"战略备选 |
| 回程只读采集本身被判定为程序行为 | 低 | 只读不产生输入特征；不使用任何自动化框架；采集层不注入伪装脚本；与 Obsidian web viewer 同类 |
| 风控持续分析后升级处置 | 低-中 | 实测确认风控云验证码与设备指纹服务**照常运行**——"没被拦"≠"没被分析"。保持低频人工使用；若出现验证码频率上升，回退评估 |

**结论**：封号风险从"一条未知"收敛为"**一条已被实测检验、且当前为低度**"——平台对 Electron 客户端的整体态度。P0b 基线未触发拦截，唯一触发的警告已定位并消除。

## 非封号项（不列为风险，仅记录处理方式）

| 事项 | 说明 | 处理 |
|---|---|---|
| 页面改版打破解析 | 属工具维护问题，**与封号无关** | 以代码围栏为唯一稳定锚点、采集与解析分层；改版后改代码即可 |
| 模型不按用户的格式要求回复 | 影响解析成功率 | 降级为"预览 + 保留原文"，不静默猜测；UI 可给出**供用户自己复制**的格式要求文案 |
| 回程应用引入"自动写盘" | 影响文件安全 | 默认只预览不落盘；写入可撤销；网页层永不获得写本地能力 |

> 已随决策移除、不再需要讨论的项：TLS 指纹差异、DBSC/Widevine 能力缺失（随 ADR-0001"不伪造"消失）；`window.chrome.*` 与 `userAgentData` 差异（**实测证明未被据此报警**，留档但不修补）；逐字注入耗时、输入法冲突、半截文本（随 ADR-0003"零注入"消失——项目已无输入层）。

## 验收标准

- **Gate 级（P1）**：
  - **A 级自动化特征逐项为零**（`navigator.webdriver`、CDP 端口、Playwright/Puppeteer 痕迹、无头特征、伪装脚本、UA 自洽性）；
  - **C 级（伪装造成的内部矛盾）零出现**；
  - **UA 规则已落实**：UA 中无 `Electron/<ver>` 与应用名标记，且 `Chrome/<ver>` 与真实内核版本一致；
  - **P0b 实测无平台针对性拦截**（无验证码、无异常提示、账号无异常）；基线警告已定位为 UA 自报标记并消除；
  - B 级差异已如实记录留档（**不作为修补任务**）。
- **功能级（P2–P4）**：
  - **程序全程不向网页写入任何内容**（代码审查：无 `SendInput`、无 `sendInputEvent`、无 DOM 写入、无剪贴板代写、无模拟回车/点击）；
  - 出程完全由用户手动完成（复制、粘贴、写提示词、发送）；
  - 打开 UTF-8 与 GBK 文件均无乱码；
  - 编辑器渲染进程无文件系统能力，网页视图无任何文件通道；
  - 进程重启后 DeepSeek 登录态保持；
  - 全程无 Node 包装的业务网络请求（抓包佐证）。
- **闭环级（P3 的增强判定，仍属功能范围）**：
  - 用户提示词里给出格式要求时，一次人工按键即可完成"解析 → diff 预览 → 应用 → 撤销"全流程；
  - 模型不按约定输出时，原文完整保留、界面不崩、无静默丢弃；
  - 网页视图在整个回程链路中始终只读。
- **完成条件**：所有非延迟步骤为 `done`、无 `blocked`、验证结果已记录，随后由 `dev-distill` 执行归档与知识沉淀。

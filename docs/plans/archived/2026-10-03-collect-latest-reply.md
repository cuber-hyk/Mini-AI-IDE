# 采集策略重设计：只采最新回复 + 消费判定

- 实现记录：2026-10-03 L1–L5 全落地，单测 153 → 171，build/typecheck 全绿；当时仍保留 P3-5 真实页面实测工作。
- 来源：用户实测反馈（两轮对话后采集拿到旧回复；最新回复的 markdown 嵌套围栏未被采集）

## 1. 现象与根因

### 现象 1：第一次采集应用后，继续对话再采集，拿到的仍是旧回复

根因在 `replyCollector.ts` 策略 1/2 的容器选择规则：

```text
querySelectorAll('[class*="markdown"]')  →  文档序遍历
取「含 <pre> 最多的容器」，n > bestCount 严格大于才更新
```

- 多轮对话后页面有**多条 AI 回复、多个 markdown 容器**。每条回复 1 个 `<pre>` 时
  全部平局 → **停在 DOM 里第一个 = 最旧的回复**。
- 即使不平局，「pre 最多」也与「最新」无关：旧回复代码块多就永远选旧的。
- 策略 1 返回非空即停止尝试 → 后面「取最后一条（最新）」的策略 4 永远不会执行。
- **第一次采集正确只是因为当时会话里只有一条回复**，缺陷被掩盖。

### 现象 2：最新回复是 ```markdown 包裹（内嵌 ```python），采到的却是裸代码

是现象 1 的直接后果：定位错容器 → 拿到**旧回复的 python pre**（裸代码），
不是最新回复的 markdown pre（innerText 含内层 ```python 围栏行）。

迷惑点：采集结果里的「### 文件：Mini-AI-IDE-test.md」标题是对的——pathHint 是
**整页扫描取最后一条**，恰好取到最新回复的标题。旧代码 + 新标题拼接。

### 连带缺陷（定位修好后会立刻暴露，必须一并设计）

1. **采集脚本外围栏写死 3 反引号**：最新回复内容本身含裸 ```（内层 python 块的
   闭合围栏）→ `splitFences` 把内层闭合行误判为外层闭合 → 截断/多出空块。
   提示词组装侧（`snippet.ts` fenceFor）已有自适应规则，采集侧没有复用。
2. **pathHint/rangeHint 整页扫描**：最新回复不带路径标题时会取到**历史回复**
   的路径 → 错配。线索提取必须限定在最新回复容器内。

### 约束：为什么「已消费」不能打在页面上

零注入（ADR-0003）：程序对网页只读不写，不能往 DOM 加任何「已读」标记。
消费状态只能放**主进程**，用内容指纹比对实现。

## 2. 设计

### 设计原则

1. **新鲜度优先**：一切判据围绕「文档序最后」；「pre 最多」「文本最长」这类
   与新鲜度无关的判据全部废弃。
2. **一次采集消费一条回复**：状态在主进程（指纹），页面零改动。
3. **内容保真**：pre 的 innerText 原样保留（内层 ```python 围栏行是 md 文件
   内容本身，不剥不猜）；外围栏自适应加长保证解析配对。
4. **失败显性**：无新回复 / 定位失败 / 回复生成中，都给明确提示，绝不静默回退。

### L1 定位层（页面脚本，只读）——产出"最新回复"候选文本

- **S1 最新回复容器**：markdown 语义容器按**文档序取最后一个**；容器内多个
  pre 按文档序拼接（一条回复可以多个代码块）；「### 文件：」「### 范围：」线索
  **只从该容器内**提取，废弃整页扫描。
- **S2 最新回复容器整体文本**：容器无 pre 时用（纯文本回复 / 结构变化）。
- **S3 文档序最后一个 pre**：S1/S2 都失败时的结构兜底（最后一个 pre 大概率
  属于最新回复）。
- 删除「整页 pre 拼接」「最长文本」类策略：每一层都必须保持「最新」语义，
  不接受"有内容就行"。

### L2 消费判定层（主进程，纯状态）

- 采集成功后记录：`会话键 → { 内容指纹(sha256 截断), 长度, 时间 }`。
  会话键 = sanitize 后的 URL pathname（DeepSeek 会话 ID 在路径里，天然隔离会话）。
- 采集时：最新回复文本 → 指纹与记录相同 ⇒ **不解析、不产生变更**，返回明确
  状态「最新回复已采集过，无新内容」；不同 ⇒ 正常解析并更新记录。
- 「应用」与「放弃」**都算消费**（指纹方案自动满足）：放弃后不对话再采集 →
  提示无新内容；放弃后重新生成 → 新内容新指纹 → 正常采集。
- 切换会话（URL 变）→ 新键互不影响；重启清空（重启后对同一回复需再确认一次，
  可接受，不做持久化）。
- UI 契约：`ReturnPreview` 增加 `noNewContent?: boolean`（或等价 note 约定），
  预览面板显示提示且不产生待应用条目。

### L3 提取层（采集脚本细节）

- pre 内容取 `innerText` 原样，保留内层 ```python 行、空行与缩进。
- **外围栏长度 = 内容内最长连续反引号序列 + 1（最少 3）**——与提示词组装侧
  fenceFor 同规则；解决嵌套围栏被 splitFences 截断的问题。
- 语言标注从 code/pre 的 `language-xxx` class 提取，取不到就不标（不伪造）。

### L4 提示词规范层（formatSpec 模板补充，双保险）

模板补一条「围栏怎么写」的约定：

- 纯代码文件（.py/.ts/…）：代码块语言标注与文件扩展名一致（```python）；
- 文本类文件（.md/.txt/…）或内容含 ``` 的：**外层围栏必须比内容里最长的
  反引号序列长**（直接写法：外层用四个反引号 ````markdown，内层保持三个）；
- 定位：模板只是"请求模型配合"，**不构成正确性依赖**——L3 的自适应才是硬保障；
  模型不守规范时链路仍正确。
- 修正用户口述笔误：文本文件应包 ````markdown（语言标注跟**文件类型**走），
  不是 ```python。

### L5 反馈层

- 「无新回复」：明确提示，不产生待应用条目（不回退旧内容）。
- 「回复生成中」（可选增强）：间隔约 1s 连采两次比对，未稳定则提示稍后再试；
  实现前先用 `--diagnose` 探针确认页面有无「停止生成」类只读结构特征。
- 「定位失败」：走现有 diagnostic 上报结构计数，明确报「未找到最新回复容器」。

## 3. 对用户三点想法的采纳与修正

| 想法 | 处置 |
|---|---|
| 只采最新一条回复，历史一律不参与 | 采纳 → L1「文档序最后」判据；废弃「pre 最多/文本最长」 |
| 采集后标记已消费；无新回复明确提示 | 采纳 → L2 主进程指纹（零注入不允许改页面）；「放弃也算消费」自动满足 |
| 保留 ```python 语言标识提取；提示词规范输出 | 采纳并细化 → L3 围栏自适应 + L4 模板补围栏规范；修正「文本文件用 ```python 包裹」笔误 |

## 4. 验证设计（实现后）

单测（vm 仿真 DOM，沿用 replyCollector.test.ts 模式）：

1. 多条回复容器 → 采到最新一条；旧回复 pre 更多时仍选最新；
2. 最新回复内嵌 ```python 围栏 → 采集文本外围栏为四反引号、解析后 code 含
   ```python 行、splitFences 不截断；
3. 指纹相同 → noNewContent；指纹按会话隔离；重新生成 → 新指纹放行；
4. 线索只从最新容器取：历史容器带不同路径不干扰。

实测：本例两轮对话场景（先采集应用 python 版 → 再让 AI 用 ````markdown 输出 →
再采集）应得到 markdown 嵌套版本。

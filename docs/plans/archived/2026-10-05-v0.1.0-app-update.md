# v0.1.0 发布与安装版应用内更新

## Goal And Scope

让 Windows x64 NSIS 安装版从公开 GitHub Releases 检查新版本，经用户确认下载，并在未保存内容得到处理后重启安装。发布含更新能力的 v0.1.0，并发布仅提高版本号的 v0.1.1，用已安装的 v0.1.0 验证完整升级链路。

不实现 Portable 原地替换、镜像源、强制更新、自动提交或 push。外部 Release 发布和 Git 操作在展示结果后等待明确批准。

## Assumptions And Decisions

- 用户已确认公开 GitHub 更新源、NSIS 首版更新、Portable 不原地更新，以及软件更新专用的主进程网络例外。
- `gh repo view` 核实 `cuber-hyk/Mini-AI-IDE` 公开，默认分支 master，尚无 Release。
- 使用 electron-builder + electron-updater，保持 appId、应用名、userData、分区和安装位置策略。
- 启动检查一次，原生帮助菜单允许手动检查/下载/安装；原生对话框展示版本与说明，菜单和任务栏展示下载进度。
- 不自动下载，不在普通退出时自动安装，不接受预发布版本或降级。
- 未签名产物保持现状，不将散列校验称为发布者认证。
- 用户已安装 v0.1.0，并确认先发布 v0.1.0、再发布稳定 v0.1.1 以检验通知、下载和安装；真实两版本验收在两个 Release 可用后进行。
- 用户已在展示变更后批准 v0.1.0 实现提交和 v0.1.1 版本变更提交；用户负责手动同步 GitHub，不授权代理 push、合并或删除分支。
- ADR gate: needed，软件更新网络例外与更新源形成跨模块长期边界。
- Design system impact: none，复用原生菜单/对话框，不增加渲染视图或样式。

## Fact Sources And Placement

来源：AGENTS.md、DESIGN.md、docs/capabilities/windows-packaging.md、package.json、electron-builder.config.cjs、src/main/index.ts、editorSession.ts、workspaceController.ts。

结构判定：no split；不拆既有主入口。新更新状态与副作用由具体 owner `updateService.ts` / `appUpdater.ts` 承担，`updateInstaller.ts` 等待进程确证启动，禁止更新库预先排程退出。Do not add to: src/main/index.ts 的下载、网络、版本比较实现；入口仅接菜单、生命周期和已有离开确认。

## Acceptance And Risks

- 更新操作只在主进程，编辑器仍无网络，AI 网页无更新能力和注入。
- 安装前复用 WorkspaceController 队列及 EditorSession.canLeave；批准后不再次询问而丢失放弃意图。
- 发布元数据与产物一致；不内嵌 GitHub token；文案不执行远程 Markdown/HTML。
- 按用户确认的检验流程，先提供两个版本的 Release，再用已安装0.1.0补真实 Windows 升级验证；验证完成前不宣称完整升级通过。
- 保持计划 active，直到验证和发布门禁完成；完成后归档到 docs/plans/archived/。

# 多项目工作区与 AI 主区域 UI 调整

## 目标与范围

将当前界面调整为左侧多项目工作区、中间官网 AI 对话及本地工具控制、右侧文件工作区；右侧内部从左到右为编辑／Diff 内容、目录树。借鉴本地 deepseek-harness 的导航结构、视觉层级和紧凑操作方式，保持现有工具执行与网页权限边界。

本计划仅授权范围是 UI 与顺序切换项目。多项目后台执行、多个官网视图、会话绑定、项目会话列表、跨项目草稿恢复、插件系统、自由停靠、多窗口、Markdown 专用阅读器均不在本次范围。用户最新截图只用于确认“正文左、目录右”的位置，不引入截图内其他产品功能。

## 已确认决策与实施边界

- 左侧是常驻工作区列表，可加入多个本地目录并切换当前项目；不是项目文件树。项目切换不导航、不刷新官网，不维护项目到官网会话的映射。
- 中间是官网对话及其原生输入框，下方为独立本地工具状态与控制区。工具状态不能插入官网消息流，官网 DOM 和样式不因本次 UI 改动而修改。
- 右侧文件工作区中，编辑／Diff 在左，当前项目目录树在最右。编辑与本批 Diff 共用内容位置，通过显式标签切换；保留原有连续差异、修改前后查看和撤销能力。
- 本地“编写需求”入口按需展开需求输入；沿用简洁／完整、权限、自动继续、设置与复制提示词能力，不新增任意需求自动发送。
- 本阶段保留现有目录切换保护和工具作用域规则，不为效果图提前实现后台并行；旧结果／进程跨项目保留的目标见后续议题，不把现行取消行为推广成未来并行模式规则。
- 单独持久化工作区列表，不能直接用会截断到 5 项并随访问重排的 recentRoots 代替。已有 recentRoots 可在首次初始化时用于填充列表，之后工作区列表成为常驻导航的唯一数据来源；文件菜单的最近目录继续保留其原有语义。
- 首次初始化包含已保存的当前项目，后续打开目录自动加入列表；重复目录按现有 Windows 路径规范去重。列表保持加入顺序，点击切换不重排；同名目录用父目录辅助区分，完整路径悬停可见。
- 列表“移除”只取消注册，不删除磁盘内容；移除当前项目先经原关闭目录保护，取消离开则不移除。目录失效保留列表条目，切换失败保持原当前项目并明确报错。
- UI 不新增项目级运行、排队或后台状态，避免把后续并行能力表现为已实现。
- 尺寸和动效为实施时可调参数，验收以真实窗口可操作为准，不逐像素复刻模型生成内容、商标、代码或官网示意。

## 事实来源与需要替换的规则

- 现有规则：`AGENTS.md`、`CONTEXT.md`、`DESIGN.md`、`design-tokens.json`、`docs/capabilities/app-shell.md`、`local-file-access.md`、`tool-harness.md`、`human-machine-boundary.md`。
- 几何与视图装配：`src/main/windowLayout.ts`、`src/main/index.ts`、`src/main/layoutProbe.ts`；当前是编辑器／官网／变更三列。
- 项目生命周期：`src/main/workspaceService.ts`、`workspaceController.ts`、`settings.ts`；当前一个活动根目录，recentRoots 最多 5 项，切换会重置编辑状态和工具状态。
- 本地视图：`src/renderer/index.html`、`renderer.js`、`style.css`、`fileExplorer.*`、`editorWorkspace.js`、`editorTabs.js`、`toolHarness.*`、`toolPanelLayout.js`、`promptComposer.js`、`preview.*`、`webbar.*`。
- IPC：`src/shared/contract.ts` 与各 preload。工具和文件控制仍只允许可信本地编辑器主 frame；previewBridge 保持只读快照与既有撤销能力。
- 讨论记录：`docs/2026-10-07-multi-project-parallel-development.md`。它不是本次并行开发实施计划。
- 现有 DESIGN 中“工具与输入保持左侧”“目录包含在左侧编辑器”“右侧独立变更列”等位置规则与用户最新确认冲突；实施时按最新确认替换，不把新旧布局做成双模式。

## 模块放置与视图方案

使用 `dev-split` 约束组织本次改动，不因文件行数单独重构。

- `windowLayout.ts` 继续拥有纯几何计算，增加工作区、官网区域、本地工具区和右侧内容／目录的明确预算；布局状态广播给本地渲染层使用同一份几何。
- 复用现有 editorView 作为全窗口本地布局底层，左侧工作区、中间本地工具区、右侧 Monaco 与目录由同一可信渲染进程承载。官网 webView 及 webBarView 仅占中间上部，previewView 仅在 Diff 模式占右侧内容区，不能盖住最右目录或本地操作。
- 保留官网与编辑器不同进程；不增加网页桥，不扩大网页权限。提示词独立视图与原 preload 维持窄接口。
- 本地 DOM 浮层不能穿透原生 WebContentsView：按各自本地可见区域限定菜单和设置浮层；需求／工具区展开时，主进程先更新官网 bounds。原提示词独立视图继续负责独立提示词编辑。
- 新增 `workspaceNavigation.js/css` 负责项目列表、搜索、当前项、移除与错误呈现；项目注册状态由主进程明确 owner 管理，目录切换继续汇聚 WorkspaceController，不复制文件打开链路。
- 新增 `workspaceLayout.js` 负责本地布局状态消费、拖动和区域显隐，`fileWorkspace.js` 负责编辑／Diff 显示选择；它们不持有文件写入、工具执行或网页发送逻辑。
- `src/main/index.ts` 与 `src/renderer/renderer.js` 本次分类为 defer：保留装配入口，只做必要接线，不添加项目列表或几何算法，不全面拆分其无关业务。若实际接线无法保持边界，停止扩展并更新计划。
- 尽量保留现有命令、快捷键和 IPC 名称；新增窄通道时同步 contract、preload 与调用方，删除被替代的布局接线，不保留 legacy/new 双轨。新增注册状态无需引入通用插件或停靠框架。

## 执行步骤与逐步验证

### 1. 基线与实现准备 — 已完成准备，基线截图缺失

- 按 dev-branch 建立独立任务分支；先检查工作区和既有未提交修改，不提交、合并或推送。
- 保存当前真实布局截图，核查所有即将移动的操作、IPC 调用方、DOM 依赖和 shared utilities。
- 保留本轮效果图与最新位置参考作为视觉资料，明确最右目录的修正优先。
- 验证：记录当前 1600×960、1080×600 的内容区与视图 bounds；确认可复现原先左侧工具输入和右侧独立 Diff 的基线。

### 2. 工作区列表与顺序切换 — 已实现并验证

- 添加持久工作区注册列表及初始化，渲染加入、搜索、选中、移除、同名提示、失效目录反馈。
- 打开和切换复用 WorkspaceController、EditorSession 离开保护与现有根目录广播；列表注册不创建第二个活动文件服务。
- 验证：至少加入 6 个目录，重启后完整保留、顺序不随切换变化；重复路径不重复；取消未保存确认不换项目、不移除；失效目录不丢当前项目；移除不操作磁盘文件。

### 3. 原生视图几何与区域迁移 — 已实现并验证

- 改写纯几何为左项目、中 AI、右文件区；editorView 全窗口底层，官网和本地 dock 分配独立矩形，previewView 与右内容重合但不覆盖目录。
- 迁移工具与需求到中间本地区域；迁移 Monaco 与目录到右侧，目录在最右。需求收起／展开、工具展开／拖高同步预算，保留官网可用区域。
- 支持项目栏、目录树、文件工作区及官网的显隐与常驻恢复入口，分隔条可拖动并支持键盘；项目栏与文件树有不同的宽度状态，不共用旧 sidebarWidth。
- 验证：纯布局测试覆盖边界、极小尺寸、模式切换、展开与收起；原生 bounds 不越界，所有实际可见视图无意外遮挡，本地 DOM 浮层可见区域内可点击。

### 4. 文件工作区与控件迁移回归 — 已实现并验证

- 接入编辑／本批 Diff 切换，保留 Monaco 独立文件模型、草稿、撤销栈、标签顺序和视图位置；切换显示模式不清空它们。
- 最右文件树沿用创建、重命名、删除、右键菜单、类型图标与键盘行为。选择文件走既有编辑入口；查看 Diff 不误切左侧项目或改写磁盘。
- 移动复制上下文、软件更新、工具设置和需求入口，保留工具权限、命令中断、复制回执、自动继续及发送间隔；所有状态继续来自原 owner。
- 验证：编辑→Diff→编辑保留未保存草稿与阅读位置；新文件、撤销、错误批次、运行命令、倒计时与更新浮层可见且可操作；目录切换后的旧批次不执行、不串项目。

### 5. 视觉统一与真实窗口验收 — 本地探针通过，人工验收待完成

- 按参考图统一标题层级、背景、细分隔线、图标、间距及圆角，复用 ui.css、fileIcons 和现有 token。基础值仅在 design-tokens.json 维护。
- 中间保留官网原生输入，本地编写需求收起时不出现第二个输入框；官网具体外观不做像素验收。

## 验收标准与风险

- 从左到右职责准确；最右是当前项目目录，编辑／Diff 在其左侧，左侧项目列表不混入文件树。
- 可添加并持久保存超过 5 个项目，顺序切换不改变官网当前会话；不承诺后台 AI 并行。
- 目录切换、文件写入、撤销、复制和工具回传继续使用唯一既有业务入口，旧作用域不对新项目生效。
- 布局切换不丢当前文件草稿；跨项目草稿恢复不在本次范围，沿用明确的保存／放弃／取消确认。
- 主要风险为跨原生视图遮挡、DOM 高度与主进程 bounds 不一致、旧布局设置值被误解释、菜单和快捷键恢复入口失效。旧几何偏好只在有相同语义时使用，否则采用新默认值；不保留旧布局模式。
- 当前自动继续发送的官网实测缺口必须独立说明；本次迁移验证不能把尚未验证的发送能力宣称为通过。

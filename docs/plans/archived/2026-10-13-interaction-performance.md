# 拖拽、编辑输入性能与官网加载反馈

## Goal And Scope

用户已授权实施 PERF-01、PERF-02，并检查网页启动与切换前的空白。用户已选择用当前主题显示平台名和“正在加载…”。减少高频拖拽的同步设置写盘/菜单重建与重复布局，减少编辑时不必要的全文读取及状态报告；加载反馈不冒充缩短网络加载时间。

不实施 PERF-03 至 PERF-09，不更改用户数据目录、官网会话、权限、UA、网页内容、发送协议或更新流程。主目录未提交的更新面板优化和审计归档原样保留，不纳入本任务工作树；仅复制作为来源的性能审计。

## Implementation Decisions

- 拖拽仍由 WorkspaceLayoutController 单一计算布局。移动按画面帧合并，临时几何与最终偏好提交明确区分；结束、取消和失去捕获提交最新宽度，退出前处理尚未落盘的宽度。不让迟到回执覆盖较新布局。只有影响菜单状态的变化才重建菜单。
- 编辑文档仍由 editorWorkspace 管理，Monaco 适配留在 renderer.js；在脏状态没有变化时避免重复全标签报告。降低全文读取时须保持保存、切换、撤销回原文、外部重载和退出确认的真实内容及立即脏状态，不以延迟上报掩盖编辑。
- 加载提示属于本地沙箱视图，不注入官网、不提供文件/工具/网页桥。平台 owner 依据真实加载生命周期控制显示与隐藏，成功、失败、重新加载和慢加载切回均有确定状态；正常已加载平台切换不重载。
- dev-split：既有 owner 不拆分。高频策略放 workspaceLayoutController/workspaceLayout、editorWorkspace；renderer.js 和 index.ts 只增加适配与接线。加载提示有明确独立责任，使用专用本地展示 owner，不扩展主进程入口为通用 UI 管理器。
- ADR gate：复核已有工作区布局/平台切换决策，记录新的本地提示视图责任，不改变官网只读与唯一发送边界。
- 实施分三组不重叠的代码工作；主代理负责整合、文档、验证及 Git。禁止工作代理提交、合并、推送或改主目录。

# 短 JSON 清单与具名原文块

## Goal

长命令、文件内容和修复正文无需 JSON 转义，仍须经唯一正式协议、完整批次校验、原有权限及去重后执行。

## Scope And Decisions

- 用户已接受“短 JSON＋原文块”并授权开始，2026-10-18 明确授权提交并合入主分支；本轮不推送或发布。不接 API、不改变网页写入或工具权限，不重放历史。无关未跟踪文件保持不动。
- 在同一 mini-ai-tools 正式围栏内，先 JSON 清单，后 `@@body id` / `@@end id` 原文块；仍 protocol_version:1，内部 ToolBatch 不变，短参数的既有 JSON 是同一合同的无正文形式，不另建兼容解析器。
- command、content、old_string/new_string 指定正文槽允许 `{text_ref:"id"}`；路径、工具名、权限、工作目录不插值。块名唯一、逐一引用，缺失、闲置、重复和歧义标记整批拒绝；边界行占用一个分隔换行，额外空行表示正文末尾换行。运输换行统一LF，其他字符不trim。外层围栏须长于正文内同类围栏。
- 带正文的整个容器上限200000字符，最多100块；沿用现有手动入口及草稿内存上限。模型不计算长度/hash。只接纳明确完整回复，不猜测修复。
- 草稿仍同一内存owner及来源链。增加按 body_id 替换正文块或 manifest 清单（保留其他块），content 可引用补丁自身原文块；真实 draft_id/version必需。原有短字符补丁留作小错误操作，但默认指导优先重发短清单；非法补丁不递归建草稿。执行后的命令语义错误通过新批文件编辑/执行处理。
- 旧会话需用户重新附带新版格式要求；不静默更新历史。此合同为长文本运输ADR，用户已确认方向，实施细节在本计划明确。

## Code Placement / dev-split

no split：现有 toolProtocol.ts 保留正式解析门面、参数校验及公共类型；新增纯函数 owner toolTextBodies.ts 管理原文块边界和指定字段解析，不扩大 integration/harness/store。jsonDraft.ts 保持草稿状态owner。采集只在验证发现原文还原问题时作必要改动，不拆大文件、不改工具执行能力。

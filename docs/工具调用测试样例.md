# 工具调用测试样例

在一个空白临时目录打开项目，先执行 S01。不要在真实业务项目验证覆盖与草稿丢弃。每例都提供可复制的“测试提示词”和对照用的“AI 回复”；**发给 AI 的输入是测试提示词，AI 回复是参考输出，不是需求。**

### 从 S01 开始测试

1. 在 IDE 打开空白临时目录，选择权限并开启自动采集。
2. 复制 S01 的“测试提示词”代码框内全文，粘贴到 IDE 底部需求输入框。
3. 点击“复制提示词”，把 IDE 生成的完整提示词手动粘贴到右侧 DeepSeek 网页并发送。IDE 会附加工具协议，无需另找或手写规范。
4. 回复结束后，查看 IDE 的工具结果及本地 tool-samples 文件。结果应符合 S01 的“预期”。
5. 接着用 S02 的测试提示词做查询。其他案例先完成各自“前提”，再按标注的测试方式操作。

### 两种测试方式

- **正常生成**：S01–S09、S15–S25。把本例测试提示词放进 IDE 需求输入框，再点击“复制提示词”并手动发给网页 AI。AI 生成的批次 ID、请求 ID 和说明可以不同；比较工具、参数和实际结果。若 AI 先查询资料，把工具结果复制发回，继续到本例目标操作完成。S20 需先把提示词中的资料位置替换为 S19 的真实工具结果。
- **原样回放**：S10–S14、S26–S35。这些案例需要固定错误内容或固定批次 ID，测试提示词已经包含完整回放文本。直接把整个测试提示词代码框内的文字手动发到网页 AI 的新对话，**不要经过 IDE 的“复制提示词”按钮追加正常协议**，否则 AI 可能修正反例。每次只发一个子例；S34 有三个独立提示词。实际回复必须与“AI 回复”一致才算有效输入；AI 若修复 JSON、补围栏或更换 ID，此次不能证明对应反例通过，可用下述文档自动测试验证原文。

代码框的外层五反引号（测试提示词）与四反引号（参考 AI 回复）只用于本文展示，不属于要复制的文字。原样回放提示词内的 BEGIN/END 标记只分隔资料，要求 AI 不把标记输出。不要把整份文档发给 AI。

先开启自动采集，再发送新的回复；开启时已有回复是基线，不会补执行。生成结束且出现一个完整顶层 `mini-ai-tools` 围栏后，IDE 校验、按预选权限执行。网页无法确认生成结束时可手动采集。普通解释不含工具批次，不执行。

正常每次实际执行都换新的 `batch_id`，例如 sample-07-run2；S26/S27 去重测试才刻意保持 ID。修改成功案例重跑须先还原目标原文；创建案例重跑换独立文件名或换新的空白目录重做 S01。S10–S14 只读原文或拒绝，不会改变基线。各正常修改案例使用独立文件，按前提执行即可，无需全部顺序执行。

解析预期是协议层的 batch/error/none；batch 只表示结构正确，不代表授权通过或工具执行成功。反例建议手动采集；自动采集也必须保持不执行。权限、草稿策略和确认都由 IDE 控制，AI 不能通过 JSON 改设置。

S20 的进程 ID 必须人工替换为真实工具结果；正式发给 AI 的请求应已无占位符。Bash 是否可用取决于本机环境。命令样例只输出文本或短时等待，不联网、不删除数据。

`pnpm exec tsx --test test/toolSamples.test.ts` 会直接读取本文原文：逐例检查协议预期，并在临时目录实际验证初始化、查询、成功/失败修改、命令日志和依赖行为。权限交互、真实网页完成识别、重启及 Monaco 草稿须在桌面手测，自动测试不假称覆盖这些交互。

# ADR-0003：零注入（程序不向网页写入任何内容）；验收判据是"无自动化特征"

> 本 ADR 替换了同一议题上的早期结论（原结论为"用 Win32 `SendInput` 注入选中代码"，原文件名 `2026-10-02-injection-channel-and-fingerprint-baseline.md`）。经用户澄清：**出程连"搬运代码"都不需要程序代劳**，故出程注入被整体移除。本 ADR 记录**修正后**的决策。

## 状态

已接受（accepted）。用户明确确认：**砍掉出程，"程序不碰输入框"**。

## 背景

早期方案设想由程序用操作系统级输入注入，把用户选中的代码送进网页输入框。用户指出该方案的净收益为负：

> 程序插入代码的前提同样是"我已经选中了代码"；既然已经选中，我自己 `Ctrl+C` / `Ctrl+V` 就行——**比程序代劳少一次点击，甚至更快**。

该论证成立，且推论比"换个更快的通道"更强：**出程不需要程序参与**。删除它同时消除了整类风险——程序不再向网页写入任何内容，也就不存在"输入行为"可供风控观察。

真正值得程序代劳的是**回程**：AI 回复里散落着解释、多个代码块、跨文件片段，人工比对与粘贴才是有实际成本的部分（见 ADR-0004）。

## 决策

**程序不向网页写入任何内容；一切网页交互由用户手动完成。**

| 环节 | 由谁完成 | 程序是否参与 |
|---|---|---|
| 复制代码 | 用户（`Ctrl+C`） | ❌ |
| 粘贴到输入框 | 用户（`Ctrl+V`） | ❌ |
| 写提示词 | 用户 | ❌ |
| 按发送 | 用户 | ❌ |
| 读取回复 | 程序（只读） | ✅ |
| 解析代码块 | 程序 | ✅ |
| 预览与应用到本地文件 | 程序（用户确认后） | ✅ |

具体规则：

1. **不注入键盘事件**：不调用 `SendInput`、不使用 `webContents.sendInputEvent`、不派发任何合成事件。
2. **不使用剪贴板通道**：若由程序代写剪贴板，用户仍需自己选中、粘贴并发送，环节不减反增；且引入全局剪贴板争用。无净收益。
3. **不修改网页 DOM**：不通过 `value` 赋值或任何 DOM 写入改变页面内容。
4. **不模拟发送**：不注入回车、不点击发送按钮。
5. **回程只读**：程序对网页的全部接触限于"读取已有文本"，见 ADR-0004。

### 验收判据（冻结为可枚举清单）

采集方式：在**本机 Electron 内嵌 `WebContentsView`**（默认构建、未打补丁、未伪装）中逐项核验。

| 层级 | 判据 | 判定 |
|---|---|---|
| **A 级：必须为零（自动化特征）** | 无 `navigator.webdriver`；无 CDP 调试端口暴露；无 Playwright/Puppeteer/Selenium 痕迹（含 `<session>` 类泄漏）；无无头模式特征；无任何"注入式伪装"脚本（伪装会形成内部矛盾）；UA 与实际内核自洽 | 任一不符 → **Gate 不通过** |
| **B 级：如实记录，不追求消除** | 与真 Chrome 的指纹差异（TLS 握手、Canvas/WebGL 渲染串、字体与插件列表、编解码器、`window.chrome.*` 表面） | 仅作为**知情记录**留档，用于判断"是否会被专门针对"，不作为修补目标 |
| **C 级：不得出现** | 任何"伪装后留下的矛盾"（UA 声称 Chrome 而实为 Electron、伪装指纹导致内部不一致等） | 出现即阻断并回退 |

## 备选方案

| 方案 | 为什么未采用 |
|---|---|
| `SendInput` 注入选中代码（早期结论） | 前提条件与手动操作相同（都要先选中），却多一次点击；净收益为负。 |
| 剪贴板 + 模拟粘贴 | 同上，且额外引入全局剪贴板争用。 |
| 把文本直接写入 DOM | `isTrusted: false`，最易识别的自动化证据；且违反"不修改页面"边界。 |
| 模拟回车／点击发送按钮 | 属于"程序操作界面"的核心特征，直接冲突；且由用户自己发送零成本。 |
| 验收标准沿用"与 Chrome 高度一致" | 方向错误（见 ADR-0001），且无阈值、不可回归。 |

## 后果

**正面**：

- **项目不再包含 Windows 特定原生模块**——出程注入层（含 `SendInput`、输入法处理、注入节流）整体消失，可移植性变好、风险面变小。
- 程序与网页的接触面缩到最小：**只读，不写**。
- 不存在"输入行为"，因此不存在由输入产生的自动化特征。
- 判据可枚举，Gate 有明确通过／不通过语义。

**负面 / 代价**：

- 每次交互需要用户手动复制粘贴（用户评估后认为这比程序代劳更快，故接受）。
- 程序无法知道"用户到底送了哪段代码"——上下文完全由用户的提示词承载，UI 不应假装知道。

**已知风险**：平台若对"Electron 客户端访问网页"整体持负面态度，则本判据通过也不能保证可用。**该风险由 P0b 实测判定**，这是本方案唯一的存亡关口。

# Mini-AI-IDE 预期功能：网页版 AI 与本地工具协作

讨论日期：2026-10-06。

本文记录讨论后的产品目标、功能范围、工具与命令行为，作为后续设计和开发的输入。它不是当前能力说明，也不是已批准的实施计划。标为“建议”或“待确认”的内容不能在实现时直接当作用户决定。

实施记录见 `docs/plans/archived/2026-10-06-tool-harness.md`；实现后的当前规则见 `docs/capabilities/tool-harness.md`。本文件保留讨论背景，不作为运行时事实来源。

## 1. 产品目标与角色

**AI 负责判断并生成规范请求；IDE 自动采集请求、按权限自动执行本地工具、整理真实结果；用户负责把结果粘贴发送回网页版 AI。** 自动采集与自动执行已获用户确认，采集由 IDE 自行触发。

用户给出需求后，不再承担逐个找文件、复制源码、截图目录、拼接报错或手工操作每个工具的工作。IDE 不代替用户点击网页、粘贴或发送。

**IDE 是通用工具基础设施。网站、游戏、桌面软件或其他用户项目属于下游应用，不决定 IDE 的工具设计。** AI 决定执行什么命令、读取什么资料，以及如何解释结果；IDE 不内置按下游应用类型区分的专用排错流程。

| 角色 | 职责 |
|---|---|
| AI | 理解需求，决定需要读取、搜索、修改或运行什么，根据工具结果继续判断 |
| IDE | 只读采集，协议解析，权限检查，执行，进程管理，修改校验，结果整理与展示 |
| 用户 | 提出需求，选择权限，处理需要批准的操作，把结果送回 AI，验收最终效果 |

模型用于判断和生成请求；路由、参数校验、权限规则、去重、调度、输出截断和状态管理由确定性代码完成，不额外调用模型处理这些工作。

## 2. 已确认的方向

- 继续使用官方 AI 网页，不逆向 API，不代理大模型网络请求。
- 未来支持 IDE 自动只读采集新回复，采集后工具按当前权限自动执行；自动采集提供开关，保留手动入口。现有版本仍需点击“采集回复”，本文记录的是已确认的未来方向。
- AI 使用规定格式请求工具；自然语言提及、普通代码示例和引用资料不能触发执行。
- 每次回复只能输出一个最终确定的可执行方案和一个正式请求批次；备选方案只用于讨论，不能混入可执行内容。需要用户选择时先提问，不输出可执行批次。
- 读取文件、获取片段、列目录、搜索、执行命令和应用修改是预期核心能力。
- 命令执行包含 Bash 等所支持 shell 的命令；报错作为工具执行结果返回，排查过程由 AI 通过通用工具组合完成。
- IDE 自动整理工具结果，用户批量复制、手动粘贴和发送。不得自动覆盖剪贴板或把结果写进网页。
- 输入框底部常驻“请求批准”“按规则自动”“完全访问权限”三种模式，用户在执行前自行选择，后续操作遵循当前所选权限。
- 完全访问允许项目外文件访问及联网命令，在当前 Windows 账户权限内执行。
- 文件有未保存内容时，提示“继续应用 AI 修改（替换未保存内容）”或“停止修改”；继续时采用 AI 基于其原文生成的结果，设置支持记住处理方式。
- 本地操作按所选权限执行；权限不会改变网页只读、进程隔离、真实 UA 和会话持久化边界。
- 工具失败如实返回，不把写入成功等同于构建通过，也不把构建通过等同于功能满足需求。

## 3. 预期工作流程

1. 用户打开项目，在输入框底部预先选择权限模式，开启自动采集，把需求和必要的协议说明手动发送给 AI。
2. AI 输出完整、规范的工具请求批次。
3. IDE 自动只读检测新回复，确认回复结束后采集并校验完整请求，建立执行记录，不需要每轮点击“采集回复”。
4. IDE 检查每项权限：允许的自动执行，需要批准的由 IDE 显示权限请求，禁止或被用户拒绝的返回拒绝结果。
5. IDE 按请求顺序和依赖执行，展示状态，整理整批结果。
6. 用户检查并复制本批结果，粘贴到 AI 网页并发送。
7. AI 根据结果输出修改或下一批工具请求，IDE 继续处理。

用户参与消息传递仍是每轮协作的一部分；不承诺只输入最初需求便能全程无人参与。

## 4. 权限模式

用户在输入框底部预先选择权限模式，IDE 执行时使用当前模式。完全访问允许访问项目外文件和执行联网命令。

| 模式 | 文件读取、目录与搜索 | 文件修改 | 命令执行 |
|---|---|---|---|
| 请求批准 | 授权目录内自动执行 | 展示差异，批准后执行 | 展示具体请求，批准后执行 |
| 按规则自动 | 在规则允许的范围自动执行 | 命中允许规则自动执行，其余请求批准 | 命中允许规则自动执行，其余请求批准 |
| 完全访问权限 | 可访问当前 Windows 账户有权限访问的项目内外文件 | 不逐项请求权限批准，仍做一致性与冲突校验 | 可执行联网命令，在当前 Windows 账户权限内运行，不逐项请求权限批准 |

### 4.1 共同规则

- 当前模式在输入框底部始终可见，用户可随时切换；后续执行使用当前模式。切换影响尚未启动的请求，不把正在运行的进程描述为已经受新权限约束。
- 完全访问不自动提权、不提供管理员身份，也不跳过协议校验、去重、未保存保护或原文匹配检查。
- “按规则自动”采用确定的允许、询问、拒绝规则，不承诺准确识别所有危险命令。
- 建议规则优先级为：明确拒绝优先，其次询问，再次允许；没有规则覆盖的操作询问。
- 权限设置只能由本地用户修改，AI 请求、网页文本和项目文件不能自行切换权限模式。
- 权限管理及批准请求的发起者是 IDE。AI 仅输出工具名称与内容，不负责决定能否执行、不替 IDE 向用户索取权限。
- 需要权限时由 IDE 显示工具、参数和批准选项；批准后执行，拒绝则不执行，返回“权限拒绝”的工具结果，带回批次和请求 ID。建议使用明确的 `permission_denied` 原因码；整批结果中的该项仍由用户送回 AI，AI 再判断下一步。
- 批准界面展示工具、实际参数、工作目录及权限范围。建议支持“仅这一次”和“为当前项目保存规则”。
- 保存命令授权时不能只依赖脚本名称；项目脚本或执行配置变化后的授权复核方式需在权限设计阶段确定。
- 文件与网络权限限制必须说明实际执行保障。设定工作目录不构成文件系统沙箱，检查工具参数也不能限制命令启动的子进程。
- 未实现系统级隔离前，不能宣称一个获准运行的任意命令“只能访问项目内文件”或“无法联网”。
- 暂停自动采集与停止进程是不同操作，应分别提供；当前执行、待批准和结果记录均可查看。

### 4.2 已确认的交互决定

- 权限由用户提前在输入框底部选择，不设置独立的首次权限选择流程。
- 未保存内容提示提供“继续应用 AI 修改（替换未保存内容）”和“停止修改”。设置提供“每次询问”“继续修改”“停止修改”三个处理方式；用户可以在设置中调整记住的选择。
- “继续修改”采用 AI 基于其所用原文计算出的结果，不把当前未保存草稿当成新的修改基线，不自动合并草稿。IDE 保存自己提供的上下文版本，不根据复制动作推断 AI 已收到内容。
- 用户确认的例子：磁盘已保存内容为 A，用户在编辑器改为 B 但未保存；AI 拿到 A 并生成 C。选择继续时应用 C，沿用现有应用修改的写盘行为，磁盘与编辑器均更新为 C，B 不参与计算、合并或提前保存。成功后未保存标记清除，后续构建验证 C；写入失败时保留原有磁盘与草稿状态并报告失败。
- 未保存的 B 与 A 不同，由上述提示或记住的设置处理；如果磁盘原文已经从 A 变成另一个已保存版本，则属于原文变化，仍按一致性校验报告冲突，不能借继续处理草稿绕过。
- “停止修改”保持受影响文件不变，返回停止结果，依赖该修改的请求不继续；其他独立项按既有批次规则处理。
- 完全访问允许项目外文件及联网命令。现有本地文件工具只允许已打开根目录内访问，实施时需更新相应工程边界与 ADR；不得扩大 AI 网页的本地文件权限或代理大模型请求。

## 5. 预期工具清单

以下工具名和参数为建议接口，尚未锁定最终协议。每个工具只有一个明确入口；相同业务不同时保留新旧两套执行逻辑。

| 工具 | 参数示意 | 结果与用途 |
|---|---|---|
| `get_project_info` | 项目上下文标识 | 项目结构摘要、依赖声明、可用脚本、关键配置路径及实际环境信息 |
| `list_directory` | `path`、`depth`、过滤与数量上限 | 文本目录树或条目列表，注明忽略项、错误及截断情况 |
| `search_files` | 文件名或路径模式、搜索范围 | 匹配文件路径，区分未找到和搜索失败 |
| `read_file` | `path`、可选起止行或分页位置 | 全文或片段，含来源、范围、版本信息、完整性说明 |
| `search_text` | 查询文本、范围、上下文行数 | 文件、匹配位置及原文片段，支持必要的进一步读取 |
| `apply_changes` | 明确的新建、替换、覆盖操作 | 复用现有修改计算、原文匹配、差异、写盘与撤销能力，逐项返回结果 |
| `run_command` | 命令、shell、工作目录、前台或后台、超时 | 执行记录；前台返回退出结果，后台返回进程标识与当前输出 |
| `get_process_output` | IDE 进程标识、输出游标 | 获取该进程后续输出和最新运行状态，避免反复返回整份日志 |
| `stop_process` | IDE 进程标识 | 停止本次 IDE 启动的任务并返回实际结果，不接受任意系统 PID |

### 5.1 文件与上下文要求

- AI 可批量请求多个文件，无需用户逐个打开。
- 搜索使用项目内容和明确参数，不猜测未提供的文件内容。
- 全文、片段、未保存缓冲内容与磁盘内容必须明确区分；读到哪个版本，结果就说明哪个版本。
- 读取原文保留缩进、空白与换行，不由模型改写。行号作为查询位置和展示信息，不作为修改定位依据。
- 局部修改用 old_string/new_string 唯一精确匹配原文；所有实际操作统一工具请求，定位语义不能退回猜行号或模糊匹配。
- 项目摘要先提供结构、依赖与入口，具体文件按需读取；不默认把全仓库源码发送给 AI。
- 排除依赖目录、构建产物和二进制等噪声，结果说明过滤与限制。敏感文件的默认规则待权限设计确认。
- 项目环境区分 Electron 内置运行时与实际执行项目命令的运行时；没有检测的信息标为未知，不伪造版本。
- AI 新建、改名、删除等进一步文件管理需求，可在后续扩展同一工具体系；删除专用工具是否纳入首版尚未确认。

### 5.2 命令与进程要求

- 命令工具支持 PowerShell 与 Bash，请求明确指定使用的 shell，执行本机配置可用的对应环境。shell 未安装或无法启动时如实返回错误，不将 Bash 命令当成 PowerShell 命令执行；Bash 环境的接入方式在实现设计时确定。
- 命令既可以是配置好的项目脚本，也可以是 AI 输出的规范命令请求；是否执行由当前权限决定。
- 输出记录包含实际命令、shell、工作目录、开始与结束时间、stdout、stderr、退出码或终止原因。
- 报错属于命令结果，按实际 stdout、stderr 和退出状态返回。IDE 不因项目是网站、游戏或软件而启动不同的错误采集任务，也不替 AI 选择排查命令。
- 命令结果反映该进程实际产生的输出，不能保证包含下游应用所有错误。缺少信息时由 AI 请求读取日志、执行进一步命令或使用其他已有通用工具。
- 输出长度与保留大小受限；保留可继续读取的原始结果，并注明截断，不能截断后仍声称完整。
- 命令超时、用户取消、启动失败和非零退出码是不同状态。成功启动不等于成功完成。
- 后台开发服务器启动后及时返回进程标识，支持读取新增日志和停止；不等待服务器退出才提供第一份结果。
- 第一版建议不支持依赖交互式输入的终端会话；出现密码、选择菜单或其他交互需求时明确提示，不能一直挂起。
- 不自动重跑具有副作用的失败或未知状态命令。停止请求完成后仍应说明子进程清理是否成功，不能仅凭发出停止信号宣称全部结束。
- 工具运行允许用户停止；IDE 重启后不得把之前的命令当成未执行并自动再次启动。

### 5.3 命令示例

下面是工具应能够承载的典型任务，不是产品预置允许列表，也不表示无需权限检查。工具不限定 Node.js 或 pnpm 项目，具体命令由 AI 根据下游项目提出。

| 任务 | 示例 | 预期处理 |
|---|---|---|
| 运行 Bash 命令 | Bash 中的 `pwd`、`ls -la` | 使用明确指定的 Bash 环境，返回原始输出或执行错误 |
| 检测项目环境 | `node --version`、`pnpm --version` | 返回实际执行环境或找不到可执行程序的错误 |
| 检查项目状态 | `git status --short`、`git diff` | 返回输出，不擅自提交或修改 Git 状态 |
| 安装依赖 | `pnpm install` | 按权限运行，记录网络或安装失败；它可能联网、执行脚本和写文件 |
| 构建 | `pnpm run build` | 返回构建输出及退出码，不将构建通过表述为功能验收通过 |
| 类型检查或测试 | `pnpm run typecheck`、`pnpm test` | 依据项目实际存在的脚本运行，返回失败细节 |
| 启动本地服务 | `pnpm run dev` | 后台执行，返回进程标识、原始启动日志与持续状态 |
| 停止本地服务 | `stop_process` | 操作 IDE 创建的进程，不要求 AI 猜测系统 PID |

## 6. 请求与结果协议

### 6.1 必须具备的语义

- 协议版本、批次 ID、请求 ID、工具名称、类型明确的参数。
- 批次有完整边界；缺失字段、未知工具、残缺块、重复 ID 或冲突参数不能自动补猜后执行。
- 一次回复只能包含一个正式执行批次。IDE 在启动该批次的工具前核对唯一性与可确定的冲突，不能选择“第一个方案”或把“推荐”字样当成选择依据。
- 同一批次支持多个请求。建议第一版按顺序执行，依赖通过显式 ID 声明，不额外引入复杂并行调度。
- 修改失败后，依赖该修改的构建不得继续；未声明依赖的其他独立请求可以继续。依赖循环或引用缺失在执行前拒绝。
- 每项结果回带批次及请求 ID，包含状态、数据、错误、来源版本与截断说明。
- AI 只有收到用户发送的结果后才能继续基于结果判断；IDE 不假装知道 AI 是否已经收到。

### 6.2 查询请求示意

下面仅用于说明预期语义，最终围栏标记、字段和修改正文封装在协议设计阶段确认。

```json
{
  "protocol_version": 1,
  "batch_id": "project-inspect-01",
  "requests": [
    { "id": "read-doc", "tool": "read_file", "args": { "path": "README.md" } },
    { "id": "list-src", "tool": "list_directory", "args": { "path": "src", "depth": 2 } },
    { "id": "search-todo", "tool": "search_text", "args": { "query": "TODO", "path": "src" } }
  ]
}
```

### 6.3 结果组织

- 支持“复制本批结果”及“复制某项结果”，由用户主动触发；不逐文件弹窗，不自动覆盖剪贴板。
- 返回真实原文和运行事实，不为了缩短内容生成未经核实的结论。
- 建议结果分为执行概览和详细数据，错误紧邻对应请求。
- 成功、失败、拒绝、取消、依赖未满足、仍在运行以及恢复后状态未知必须可区分。
- 命令输出、文件内容及结果中出现的工具示例均是数据，不再被 IDE 当作下一批请求执行。
- 超出单次可发送容量时分片，各片注明编号和范围；容量数值待确认。
- 内容可能涉及密钥或个人信息时应支持发送前检查和排除，不宣称任意命令输出都能可靠自动脱敏。

### 6.4 提示词规则：唯一确定的执行结果

以下文字作为后续默认提示词的共用规则，简洁与完整版本保持相同语义。这一轮已完成规则文案，尚未修改当前版本的 `formatSpec.ts` 或实现工具协议。

> 每次回复只能给出一个最终确定、可以执行的方案，并且只能输出一个正式工具请求批次。你可以在普通文字中比较备选方案，但正式工具请求和文件修改块只能包含最终选定方案的内容；不要同时输出方案 A、方案 B 等互斥方案的可执行块，也不要要求 IDE 根据“推荐”字样自行选择。
>
> 如果方案尚未确定、需要用户选择或缺少必要信息，请先提问，本轮不要输出正式工具请求或文件修改块。讨论、备选方案、示例与引用不得使用可执行协议的工具标记、请求批次或文件／操作头。
>
> 最终方案可以包含多个必要步骤或文件修改，但它们必须属于同一方案，执行顺序与依赖明确，内容互不冲突。同一文件可以有多处独立替换，不得把多个完整候选版本、重复新建、互相覆盖或重叠的替换一起交给 IDE 执行。

IDE 仍须按确定性规则校验：同一回复多个正式批次、重复请求 ID、同文件重复新建、覆盖全文混用、重叠替换及明确的互斥请求均不能靠提示词放行。返回冲突原因，阻止冲突项与依赖项，完全访问模式也不跳过此校验。提示词降低歧义，但不能保证 IDE 识别所有语义上的冲突，不能据此宣称任意多方案输出都能可靠自动判断。

## 7. 采集与请求执行可靠性

当前实现是手动触发采集：`src/renderer/webbar.js` 在“采集回复”按钮的点击处理里调用桥接接口，主进程完成网页只读采集。当前没有自动监听新回复并自行发起采集的功能。

自动采集是已确认的未来功能：IDE 只读监听新回复，确认回复结束和请求完整后自行采集，用户不必每轮点击按钮。支持开关并保留手动入口；采集后的工具按权限自动执行。开关的持久化及恢复行为在计划阶段设计，新会话不得重放历史请求。

- 自动模式读取最新 AI 回复，不点击网页、不写 DOM、不合成事件、不启用 CDP 或浏览器自动化驱动。
- 不以正文长时间未变化作为唯一完成判据；需要回复结束状态与完整协议批次共同支持执行。无法确认时等待或显示诊断，不能冒险执行半条命令。
- 开启自动采集、重启、刷新或切换对话时建立基线；不会自动执行已有历史回复。
- 幂等记录区分未执行、运行中、已完成与状态未知。同一请求重复出现不重新执行；同 ID 内容变化视为冲突，不默默当成新操作。
- 执行开始记录应先于副作用，并在必要范围持久化，防止重启后重放。中断且结果未知时要求明确处理，不承诺任意外部命令具有严格 exactly-once 保证。
- 请求关联本地项目和当前对话上下文；切换项目后旧请求不落到新项目，待批准项重新核对当前状态。
- 失败只影响对应请求与依赖项，不把部分成功显示为整批成功。重新尝试是明确的新执行，不由重复采集触发。
- 页面结构变化、回复截断、解析失败等状态对用户可见；不改用逆向接口补采。
- 保留手动重新读取入口用于诊断，但它使用同一去重和执行入口，不成为另一套工具实现。

## 8. 修改与工具结果反馈

- 新建、替换、覆盖继续复用现有能力；自动批准只省略权限询问，不省略差异计算、原文基线与文件身份校验。
- 遇到未保存内容时，按设置询问、继续应用 AI 结果或停止。继续允许用 AI 结果替换未保存草稿；差异计算使用 AI 对应原文，不基于草稿重算或自动合并。
- 以 A／B／C 场景为准：继续修改将 A → C 的结果写盘并同步编辑器，B 被替换；停止则磁盘保持 A、编辑器保持未保存的 B。后续构建应使用实际已保存的结果 C。
- 同文件操作冲突、old_string 零次或多次匹配、文件外部变化与写入失败均返回准确原因。
- 修改记录可查看前后差异、对应请求和撤销入口；已有撤销范围和限制如实保留。
- 验证命令优先由 AI 显式请求，或由用户明确配置在修改后执行；不擅自增加一套隐式运行规则。
- 检查结果区分“修改已应用”“命令已启动”“检查通过”“功能待验收”。
- 工具结果保留对应请求、实际输出、修改状态与执行环境，供 AI 决定下一步；IDE 不自动生成面向某种下游应用的诊断任务。
- AI 可以先运行命令，根据报错再请求读文件、搜符号或读日志，修改后再次运行命令。IDE 负责这些通用工具的执行和反馈，不解释下游业务是否正确。

## 9. 预期界面

这是功能要求，不锁定最终布局或视觉设计。

- 输入框底部常驻权限模式选择，显示当前项目和采集状态，提供自动采集开关并保留“采集回复”手动入口。
- 设置中可调整未保存内容的处理方式：每次询问、继续修改或停止修改。询问提示提供相应操作及记住选择的选项。
- 工具任务列表，显示批次、请求、目标、运行状态、错误与持续时间。
- 待批准请求可查看详情、批准或拒绝；完全访问模式不逐项打断。
- 结果面板支持整批复制、单项查看、原始日志与后续输出获取。
- 文件修改展示差异与撤销；自动应用后仍能回看。
- 运行任务提供停止操作，暂停新请求与停止已启动进程明确区分。
- 错误保留可见入口，正常操作无需逐项弹窗。

## 10. 建议实现顺序

这是范围建议，不是时间承诺或已批准实施计划。

| 阶段 | 目标 | 交付重点 |
|---|---|---|
| A | 建立统一的工具请求与结果链路 | 完整协议、请求身份、去重、状态、三种权限、批量结果、只读资料工具 |
| B | 完成修改与命令的本地闭环 | 复用现有修改能力、前后台命令、输出读取、超时与停止、依赖失败处理 |
| C | 完善通用工具能力 | 更精细的项目摘要、文件依赖或符号地图、结果查询与管理；按实际需求选择 |

首个可用版本应覆盖 A 和 B 的基本能力，形成读取、修改、命令执行与结果反馈的完整工具链。

## 11. 验收场景

| 场景 | 应观察到的结果 |
|---|---|
| AI 请求三个文件与一个目录 | IDE 自动收集并生成一份结果，用户无需逐个打开或截图 |
| AI 输出普通示例命令 | 不属于正式工具请求，不执行 |
| 回复包含方案 A／B 的互斥文件修改块 | 不根据“推荐”字样选方案；确定性冲突校验返回原因并阻止冲突项与依赖项 |
| 回复包含两个正式执行批次 | 启动工具前拒绝该回复的执行批次，要求 AI 输出一个确定批次 |
| AI 需要用户选择方案 | 只输出讨论和问题，不产生可执行批次，IDE 不启动工具 |
| 同一最终方案修改同文件多个独立位置 | 原文匹配唯一且区间不重叠时允许，不把同文件多处修改误判为备选方案 |
| AI 新回复完成且自动采集开启 | IDE 自行采集，按权限执行工具并生成结果，无需每轮点击采集 |
| 工具请求仍在流式生成 | 不执行；完整结束后才建立批次 |
| 同一回复重复渲染或重复读取 | 请求不会重复运行，已完成结果仍可查看和复制 |
| 开启自动采集时页面已有旧命令 | 旧命令不执行，只处理新的有效请求 |
| 项目文件不存在或无访问权限 | 返回明确失败，其余独立读取可继续 |
| 请求批准模式运行命令 | IDE 发起权限请求，批准前没有进程启动；用户拒绝后该项返回“权限拒绝”，结果可送回 AI |
| 按规则自动模式 | 允许项直接执行，未覆盖项询问，禁止项拒绝 |
| 完全访问模式执行普通修改和命令 | 不出现逐项权限询问，校验失败和运行错误仍如实显示 |
| 执行前在输入框底部切换权限 | 尚未启动的请求按当前模式处理，不出现独立的首次权限选择流程 |
| 完全访问请求项目外文件或联网命令 | 在当前系统账户权限内执行，不以项目边界或联网为由额外请求批准 |
| 修改失败但后续构建依赖它 | 构建标为依赖未满足，不检验一个未完成的修改并误导 AI |
| 磁盘为 A、编辑器有未保存 B，AI 基于 A 生成 C | 继续时磁盘与编辑器均为 C，未保存标记清除；不基于 B 重算、不自动合并、不先保存 B |
| 修改目标存在未保存草稿 | 提示继续应用 AI 结果并替换未保存内容，或停止；有已记住设置时按设置处理 |
| 已记住未保存处理方式 | 后续同类操作遵循设置，用户可修改该设置；原文失效仍报告错误 |
| 停止未保存文件修改 | 文件与草稿不变，返回停止结果，依赖该修改的请求不继续 |
| 构建报错 | 结果包含实际命令、目录、退出码和错误输出，用户无需手工拼接日志 |
| 下游应用类型不同 | 使用相同的通用工具和结果协议，不自动触发网站、游戏或软件专用排错流程 |
| 命令未提供足够的错误信息 | 返回实际输出；AI 可继续请求读取日志或执行命令，IDE 不伪造缺失信息 |
| 开发服务器持续运行 | 及时返回 IDE 进程标识，支持获取新日志和停止 |
| 超时、取消或重启 | 状态明确，命令不被无提示重跑；未知执行结果不冒充成功 |
| 输出超长 | 返回截断或分片标记，可以继续读取，不能声称输出完整 |
| 项目切换 | 旧项目请求不会执行到新项目 |
| 一轮工具协作 | IDE 自动完成采集，按权限执行工具并整理结果；用户发送需求与结果 |

## 12. 未纳入当前范围

- 自动向 AI 网页粘贴、点击发送、上传文件，或改走模型 API。
- 伪造浏览器身份、增加反检测能力、修改 Chromium 或引入网页自动化驱动。
- 为解析、权限路由、重试或格式转换额外调用模型。
- 全自动部署发布、多 Agent 调度、通用浏览器自动化、完整 VS Code 级扩展系统。
- 面向特定下游应用的专用错误采集、诊断流程或业务判断。
- 本轮不实现功能，不提交、不合并、不删除分支、不 push。

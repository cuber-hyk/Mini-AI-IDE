# P3 第一阶段核验报告（纯逻辑部分）

## 范围说明

P3 分两段：

| 段 | 内容 | 本报告是否覆盖 |
|---|---|---|
| **① 纯逻辑** | 回程解析器、格式模板、应用计算、目录记忆 | ✅ **本报告覆盖**（可离线充分验证） |
| ② 采集与 UI | 从网页只读采集回复、diff 预览、一键应用/撤销 | ❌ 待下一阶段（需在真实页面验证） |

按 ADR-0004，先做纯逻辑是有意的：解析器是回程链路里**唯一能完全离线验证**的部分，
先把它做扎实，采集层就只是"把文本接进来"。

## 核验结果

| 项 | 结果 |
|---|---|
| 类型检查 | `tsc --noEmit` 通过 |
| 单元测试 | **90/90 PASS**（其中回程解析 37 项） |
| 启动自检 | **35/35 PASS**（F1–F4 覆盖解析与模板一致性，G1–G3 覆盖目录记忆） |

## 已实现

1. **回程解析器**（`src/shared/returnPath.ts`）：围栏切分（``` / ~~~）、四类路径线索、
   代码块路径注释剥离、语言标注归一化、应用计算（三种模式，纯函数）。
2. **格式模板**（`src/shared/formatSpec.ts`）：短版/完整版，**示例写法与解析器识别的形态一致**
   （自检 F3 专门验证"模板与解析器一致"，防止两边各自演化）。
3. **目录记忆**（`src/main/settings.ts`）：记录上次打开的目录与分栏宽度，
   启动自动恢复；目录失效时清空记忆并**主动通知**渲染进程（避免"看似打开了目录、实际读不了"）。

## 结论

1. **P3 的纯逻辑部分已完成并通过充分验证**（37 项解析测试 + 自检 F1–F4）。
2. **三个缺陷（P3-1/2/3）都属于"对最常见输入静默失效"**：单测在这里的价值高于人工试用——
   人工试用很可能恰好碰到带注释的代码块而"看起来正常"。
3. **P3-5 是下一阶段的关键风险**：解析器必须用真实回复校准，否则"高容忍"只是纸面承诺。
4. 目录记忆（用户明确要求）已完成并纳入自检（G1–G3），且**自检会复原用户设置**，
   不会因跑自检而改变用户的上次打开目录。

> **下一阶段**：只读采集回复（`WebContentsView` 内注入**只读**脚本读取已渲染消息，
> 不修改页面）+ diff 预览 UI + 一键应用/撤销 + 真实回复校准。

# 能力：人机边界（程序不向网页写入任何内容）

AI 生成规范请求，IDE 采集与执行，用户负责把结果发送回 AI 网页。

## 职责

明确划分"程序做什么"与"用户做什么"，并把这条边界固化为可审查的约束。

## 边界表

| 环节 | 执行者 | 程序是否参与 |
|---|---|---|
| 复制上下文或工具结果 | 用户点击；当前工具批次执行结束可按设置自动复制 | ✅（只写系统剪贴板，自动复制每批一次并提示） |
| 粘贴到输入框 | 用户 | ❌ |
| 编写需求与发送提示词 | 用户 | ✅（本地组装供用户复制） |
| 按发送按钮 | 用户 | ❌ |
| 读取回复文本 | 程序（**只读**） | ✅ |
| 解析代码围栏 | 程序 | ✅ |
| diff 预览 | 程序 | ✅ |
| 执行本地工具 | IDE 按预选权限 | ✅（需要授权时由 IDE 询问，拒绝不执行） |
| 处理未保存内容 | 用户或已保存策略 | ✅（继续采用 AI 结果，停止保留草稿） |

## 硬性规则

1. **程序不向网页写入任何内容**：不调用 `SendInput`、不使用 `webContents.sendInputEvent`、不派发合成事件、不修改 DOM、不模拟回车或点击。
2. **不自动送入网页**：当前工具批次真正执行结束后可按用户设置自动复制一次，并提示，覆盖读取、搜索、修改与命令；其余复制由用户点击。取消、未知、全部未执行、历史与跨项目/会话输出不自动复制。粘贴与发送始终由用户完成。
3. **不注入改变页面的脚本**：允许隔离上下文中的只读 DOM 变化监听、真实发送/重新生成/继续生成动作识别，以及同步只读采集；不伪装身份、不写 DOM 或替用户输入。
4. 监听状态仅用于合并通知及清理，不写网页主世界、不暴露本地 IPC/文件桥；变化通知仍需真实回复结束核验和工具权限校验。
5. UI **不得假装知道用户送了什么**——程序只记录真实发送动作的新轮序号，不读取/保存输入框内容或推断需求；上下文由用户的提示词承载。

## 为什么这样划

程序代劳"把代码送进输入框"的前提，与用户手动操作相同（都要先选中代码），却多出一次点击与一段等待，**净收益为负**。删除该功能同时消除了整类"输入行为"特征与全部 Windows 原生注入代码。

## 违反检测

代码审查关注点：仓库中不应出现 `SendInput` 调用、键盘事件合成、`clipboard.writeText` 用于发送、DOM 写入型注入。**出现即为违反本能力契约。**

# 能力：人机边界（程序不向网页写入任何内容）

> 状态说明：**本能力描述的是"不做的事"**，同样需要被维护与遵守。实现后本文件记录当前事实。

## 职责

明确划分"程序做什么"与"用户做什么"，并把这条边界固化为可审查的约束。

## 边界表

| 环节 | 执行者 | 程序是否参与 |
|---|---|---|
| 复制代码 | 用户 | ❌ |
| 粘贴到输入框 | 用户 | ❌ |
| 编写提示词 | 用户 | ❌ |
| 按发送按钮 | 用户 | ❌ |
| 读取回复文本 | 程序（**只读**） | ✅ |
| 解析代码围栏 | 程序 | ✅ |
| diff 预览 | 程序 | ✅ |
| 确认写盘 | 用户 | ✅（程序提供预览与撤销） |

## 硬性规则

1. **程序不向网页写入任何内容**：不调用 `SendInput`、不使用 `webContents.sendInputEvent`、不派发合成事件、不修改 DOM、不模拟回车或点击。
2. **不使用剪贴板通道**：程序不代写剪贴板（选中即可自行复制，无净收益）。
3. **不注入任何脚本**：包括用于伪装浏览器身份的脚本与用于改变页面行为的脚本。
4. **对网页的接触只有读取**，且读取不修改页面状态（详见 `return-path-and-format-contract`）。
5. UI **不得假装知道用户送了什么**——上下文由用户的提示词承载，程序不追踪、不推断。

## 为什么这样划

程序代劳"把代码送进输入框"的前提，与用户手动操作相同（都要先选中代码），却多出一次点击与一段等待，**净收益为负**。删除该功能同时消除了整类"输入行为"特征与全部 Windows 原生注入代码。

## 违反检测

代码审查关注点：仓库中不应出现 `SendInput` 调用、键盘事件合成、`clipboard.writeText` 用于发送、DOM 写入型注入。**出现即为违反本能力契约。**

# 能力：回程解析与应用（输出格式由用户驱动）

## 目录与路径生命周期

- 采集、AI 应用、撤销和目录／条目操作通过 `WorkspaceController` 串行执行。批次与内联预览关联目录版本，切换或关闭目录前说明记录将清空，成功后清空批次、片段基线、预览和撤销快照。
- 改名／删除使匹配路径以及目录后代路径的变更与快照失效；未受影响文件保持可用。自定义应用目标也记录相对根目录的路径，旧目标不可被延迟请求重新创建。
- 编辑器目标有未保存内容时拒绝 AI 应用，要求先保存；路径比较归一化，因此绝对路径或大小写变体不能绕过检查。
- 撤销快照只存内存，并关联根目录；撤销前要求当前磁盘原文等于该次 AI 应用结果，拒绝覆盖应用后用户再次保存或外部修改的内容。
- `test/returnPathService.test.ts` 验证跨目录、路径失效和撤销保护；`pnpm run verify:workspace` 使用本地静态回复和临时 A/B 同名文件，验证真实采集→应用→改名／切换→失效链路。

## 新增文件

- 有明确目标路径的代码，目标不存在时按新增处理。三段式保留 `### 范围` 以统一格式，但新建完整写入所有代码，不按该范围截断；范围与实际行数不同或遗漏时提示，预览按实际行数显示。`ReturnPathService.prepareChange` 是采集、内联预览和应用共用的准备入口；空原文与完整新内容形成预览，预览不创建文件或目录。
- 新建路径逐级验证 Windows 名称、根目录及最近存在祖先的真实路径；权限错误、非目录父级、悬空链接或越界不视为缺失。根目录下链接父级不支持新增，根目录本身可以是合法 junction。
- 列表显示“新增文件”，编辑器显示只读虚拟标签、纯绿色增加内容与“创建文件”按钮。退出、切换或关闭时释放虚拟模型，保留已有文件草稿；预览不进入保存状态上报。
- 应用时核对采集时目标的存在状态，排他创建 UTF-8 文件和缺失父目录；同名文件出现则拒绝覆盖；将新增路径改到已有文件也不能转为覆盖。失败时清理本次创建且仍为空的目录，清理失败说明原因。
- 新增快照区别于已有空文件替换：撤销新增删除仍等于应用内容、创建时身份（dev/ino/birthtimeMs）匹配且未变为链接的文件，只清理身份仍匹配的本次新建空目录，同名重建目录保留并提示；再次修改则拒绝并保留撤销记录。文件已删除而目录清理失败时返回成功附警告，不重复撤销。
- `fs:file-changed` 携带路径、`updated/created/deleted` 和目录版本：创建刷新树并将虚拟标签转换为真实文件，删除关闭对应标签并刷新树；旧目录事件不处理。
- 有文件修改线索但缺少明确路径时保持阻塞，不能由当前文件、上次复制选区、正文唯一提及或其他代码块回填。已有文件缺少原替换范围时阻塞，不能降级为整文件覆盖。服务测试与离线 Electron 验收覆盖采集→无副作用预览→创建→撤销→再次创建及同名冲突。

### 完整 prompt 的组装方式（「复制 prompt」）

应用底部的需求输入区提供：

| 控件 | 作用 |
|---|---|
| 「要改的文件」输入框 | 可留空；多个用逗号分隔，会作为独立段落写入 prompt |
| 需求输入框 | **唯一由人写的部分** |
| 「复制 prompt」按钮 | 组装 `## 用户需求` + `## 工作环境` + `## 目录结构（摘要）` + `## 要改的文件` + `【输出格式要求】`，**写入系统剪贴板** |

实测组装结果约 527 字符（其中人写的只有一句需求），随后由用户自己 Ctrl+V 到网页输入框。

> **边界**：按钮只写剪贴板，**不写网页**。这与"程序自动注入 prompt"有本质区别——
> 后者会产生"程序在操作界面"的特征，正是项目要避免的（ADR-0003）。

### 逐块路径与范围关联

| 明确线索 | 形态 | `pathSource` |
|---|---|---|
| 围栏内首行路径注释 | `// src/a.ts`、`# a.py`、`<!-- a.html -->`、`-- a.sql`、`/* a.css */` | `fence-comment` |
| 围栏上方文件标题 | `### 文件：src/a.ts`、`### src/a.ts`、`**src/a.ts**`、`文件名：src/a.ts` | `preceding-heading` |
| 无路径线索 | 有范围／无效文件标记时提示补充；完全无修改线索则归只读其他内容 | `none` |

- 文件标题、范围标题与围栏之间允许空行；普通正文、章节标题与上一围栏形成关联边界。
- 采集器按 DOM 顺序序列化标题、语义正文和代码；优先读取 `<pre>` 内 `<code>`，不采代码框复制／下载控件。不得把全条回复最后路径套到第一个代码块。
- 明确标题支持 `.env`、`.prisma`、无扩展名及自定义扩展名，最终磁盘路径仍由白名单验证。
- 多个路径或范围冲突、格式无效时阻塞对应块；相同标题重复不算冲突。
- 没有路径、文件标签、范围或元信息错误的围栏，无论语言是否标注，统一标为 `kind: other` 并放入默认折叠的“其他内容（只读）”；展开完整显示命令、ASCII、流程图和代码示例，不提供应用入口、不执行、不计入文件数或全部应用。语言仅用于高亮。有范围缺路径、无效或冲突元信息保持阻塞；明确文件路径的 shell 块仍按文件校验。
- 每块独立验证；缺失信息只阻塞对应块，全部应用串行处理可应用块。
- 筛选和简短统计常驻，完整采集说明默认折叠在“诊断信息”；条目原因显示在详情，应用／撤销失败保留简短可见反馈及完整诊断，不让调试文本挤占列表。其他内容展开状态在同批次刷新中保留，新批次默认折叠。

### 片段替换（局部修改）与三向校验

已有文件按明确的**原文件真实行号**替换，修改全文时也使用 `1-N`：

```
### 文件：src/main/index.ts
### 范围：80-92
```ts
... 只放替换后的那几行 ...
```
```

| 环节 | 实现 |
|---|---|
| 取得片段 | 编辑器里选中代码 → 「**复制选中片段**」按钮 → 输出带上 `### 文件：` 与 `### 范围：80-92`；围栏内为原内容，不含行号，写入剪贴板 |
| 模型回显 | 格式模板第 6/7 条要求回显同一区间，且块内**不重复写行号** |
| 解析 | `matchRangeDirective` 接受 `### 范围：80-92`、`### 行：7-9`、`### lines: 7-9`、`### 位置：替换第 12-14 行`、单数字（视为单行）、倒序（自动纠正） |
| 行号前缀剥离 | 若模型把 ` 80\| code` 原样带回，解析时自动剥离，保持代码干净 |

**范围语义**：`### 范围：N-M` 指原文件待替换的闭区间，新内容的行数可以增减，范围不随新行数改变。应用计算只拼接「原第 N 行之前的内容 + 新内容 + 原第 M 行之后的内容」，不根据重复代码、空行或括号自动扩大范围。

例如 `10-10` 替换成 10 行，新内容占第 10–19 行，原第 11 行变为第 20 行；替换内容较短时，后续行相应前移。三向校验仍针对原区间执行，撤销恢复应用前的完整文件。

**三向校验（应用前，缺一不可）**：

| 校验 | 规则 | 失败结果 |
|---|---|---|
| ① 区间有效 | `1 ≤ start ≤ end ≤ 文件总行数` | `range-invalid`，拒绝 |
| ② 原内容匹配 | 当前 `[start,end]` 行的内容必须等于应用准备时取得的基线 | `content-mismatch`，拒绝 |
| ③ 上下文匹配 | 区间上一行 / 下一行（若记录了）必须仍然相同 | `context-mismatch`，拒绝 |

> **为什么必须有 ②③**：行号是**会漂移**的（文件被改过、上一轮应用过改动）。
> 没有校验时，按失效行号写入会**静默改错地方**；有校验时最坏结果只是"应用失败，请你重来"。
> 因此 `replace-lines` 模式**拒绝无校验的应用**（`expectedOriginal` 为必填）。

**模式取舍**：

| 模式 | 可靠性 | 定位 |
|---|---|---|
| 新建文件 | 完整写入代码 | 不依赖 AI 范围长度，预览后排他创建 |
| 已有文件替换（带校验） | 原区间有效并核对当前基线 | 修改全文也需明确 `1-N`，不回填缺失范围 |
| 插入光标处 | 中 | 适合追加 |

### 关键设计：代码本体与校验基线都留在主进程

`collectReply` 在主进程缓存解析结果（`collectionId` → 代码块），
渲染进程只拿到**不含代码**的预览数据，应用时用 `collectionId + index + filePath` 引用。

原因有二：
1. 渲染进程不必也不应经手大块代码文本；
2. **片段替换的三向校验需要"复制那一刻的原文"** —— 只有主进程在**读文件的同一时刻**
   抓取该区间当前内容，才能得到可信基线。此后文件若被改动，校验必然失败并拒绝写入
   （即"防行号漂移"在闭环里真正生效）。

### 撤销

- 每次落盘前把原文存入**内存**快照（最多 20 条，不落盘——避免把旧文件内容长期写进磁盘）；
- 已有文件按快照恢复原文；新增文件按新增快照删除及清理空目录。撤销失败会把快照放回，不丢失撤销机会。

### 路径与内容一起给出（不再有"只选路径"的输入）

**设计结论**：不存在"只给路径、不给内容"的有效用法 —— 模型没见过文件内容就改不了它。
因此**取消**了"要改的文件"输入框；路径作为**内容的附属品**自动生成。

**输入与输出结构统一（用户确认，方案甲）**：程序发出去的片段与提示词要求模型输出的形态
**逐字同构** —— 同一套骨架、同一套语义，模型只需"照抄骨架、只改内容"：

```
### 文件：<相对路径>
### 范围：<起始行>-<结束行>
````<语言标注>
<内容，不含行号>
````
```

| 按钮 | 用途 | 产出（骨架相同，只差范围与内容） |
|---|---|---|
| 「**复制整个文件**」 | 上下文 / 大改 | `### 文件：P` + `### 范围：1-N` + 围栏 + 全文 |
| 「**复制选中片段**」 | 局部修改 | `### 文件：P` + `### 范围：N-M` + 围栏 + 选中内容 |

两条**不可动摇的不变量**：

1. **行号只出现在 `### 范围` 行里，围栏内容里绝不写行号。**
   行号写在内容里对"人定位"与"机器写回"都是冗余，却对 `.md`/`.txt` 有真实风险：
   行号在纯文本里与正文无异，而解析器**只在存在 `### 范围` 时**才剥前缀
   （见 `returnPath.ts` 里 `stripNumberedPrefix` 的唯一调用点）——
   已有文件漏写范围时拒绝应用；模型仍应遵循内容不带行号的格式。
2. **围栏最少四个反引号**（`MIN_FENCE_LENGTH = 4`，不是固定四个）。
   内容含四个及以上**连续**反引号时，按「最长 + 1」加长，避免提前闭合、内容被截断。
   实现见 `src/shared/snippet.ts` 的 `fenceFor()`。

**整文件片段走"替换 1..N 行"**（而非无条件整文件覆盖）：因为它也带 `### 范围`，
应用前要过三向校验。这是把"结构对称"贯彻到底的副作用，属于**有意为之**——
一致性比"整文件免校验"更有价值，且校验失败时 UI 会明确说明原因。

**明确路径可人工修正**：可应用块可在预览面板改目标路径；缺失或冲突的模型路径必须补充后重新采集，不能靠渲染进程传入路径绕过阻塞。

### 历史：为什么放弃"围栏内带行号"

早期局部片段在围栏内写 ` 80| def f():` 前缀，理由是"模型可原样回显、行号不易漂移"。
实测发现两个问题：① 对纯文本文件行号会与正文混淆；② 解析器剥前缀依赖 `### 范围` 存在，
二者**同时正确**才安全，是很脆的耦合。改为"行号只在范围行"后，输入输出对称、
只有一个真相源，且 186 项单测里有专门断言锁死"内容里不出现行号前缀"。

## diff 呈现：内联标记在编辑器里，最右侧只列文件（2026-10-03 更新）

本节改过两次，这里记录**当前**形态与**为什么**。

### 当前形态

| 位置 | 呈现 | 何时出现 |
|---|---|---|
| **编辑器（同一个）** | 删除行淡红底 + 文字删除线；新增行淡绿底 + `+`，**插在被替换行的紧后面** | 采集成功后自动打开第一个可应用变更；点最右侧文件条目切换 |
| 最右侧变更列表 | 目录/文件树与片段子项、范围、增删统计、状态、集中详情操作，**不画 diff** | 一直显示 |

### 为什么是"内联"而不是"左右并排"

用户明确要求：**「diff 和原文件整合一起显示，而不是分两个板块显示」**。

因此**弃用了 Monaco 的 `createDiffEditor`**：那会把界面变成左边「当前文件」、右边「应用后」两栏并排，正是被否掉的形态。改为在**唯一那个编辑器**上叠加行内标记，编辑器里放的**始终是磁盘上那份真实文件**（一个字符都没改过）。

带来的实际好处：
- 每一行都是文件里真有的内容 —— 复制、搜索、Ctrl+F 全部正常；
- 编辑态与预览态是同一个编辑器，切换零成本，滚动位置与光标都保留；
- 视图不再需要重建，少一整套 model 生命周期。

### 为什么全部自己画

**Monaco 0.57.0 没有导出官方内联 diff API**（`monaco.d.ts` 与 `esm/vs/editor/editor.api.d.ts` 搜 `InlineDiff` 命中 0）——
VS Code 的内联 diff 依赖编辑器内部的 `InlineDiffEditor` 与语言侧 `provideInlineDiff` 协议，第三方拿不到。

所以用两个**公开 API** 自行实现：

| 机制 | 用途 |
|---|---|
| `editor.createDecorationsCollection` | 删除行标红 + 删除线 + 行号着色 |
| `editor.changeViewZones` + `addZone` | 把新增行插到指定行之后（**不进入文档、不影响 undo**） |

新增行是"画上去的"，不是真实文本。新增行的插入点由 diff 行映射中已走过的原文行数决定：保留原第 10 行后追加的内容插在第 10 行后，首行之前新增用第 0 行锚点。预览保留原文件行号；**应用之后会走一次 `openFile` 重新读盘**，标记消失，编辑器显示应用后的真实内容与行号。

### 预览期只读

进入预览时 `updateOptions({ readOnly: true })`，退出时恢复 `false`。
理由：改动还没落盘，允许在 diff 上打字会让「标记位置」与「真实文件」打架，越改越乱。
要改就退出预览回到普通编辑器。

### 画标记前的一致性闸门

标记画在**编辑器当前内容**上，因此 `renderInlineDiff` 先断言
`model.getValue() === payload.original`，不一致就拒绝绘制并提示重新采集。
理由：画错位置的标记比不画更糟。

### 自动打开与批次导航

- 采集成功后仍由主进程 `send(diffData)` **自动打开第一个可应用变更**（沿用 10-02 的结论，用户当时正是抱怨"diff 还在最右侧"）；
- payload 额外带 `siblings` / `position`，编辑器据此提供 **‹ 上一个 / 下一个 ›** 按钮；
- **应用成功后自动跳到下一个**尚未应用的变更，一路看一路应用。

### 最右侧面板的职责收敛

面板不再渲染 diff —— 它若继续画一份表格化diff，等于把同一件事在界面上呈现两遍。
每个条目只回答"改哪个文件、改哪一段、加了几行删了几行"。

条目交互：

| 操作 | 结果 |
|---|---|
| 单击整行 | 左侧编辑器打开该文件并内联标记 |
| 选中详情「应用此片段」 | 应用选中的批次片段；全部应用按原批次顺序处理待应用项，单条失败继续并汇总 |
| 「改路径」 | 收在次级位置 —— 模型偶尔给错路径，这是唯一纠错入口，但默认不占视觉 |

### 跨进程高亮同步

编辑器与最右侧面板是**两个独立渲染进程**（ADR-0002），彼此不能直接调用。
用户用「上一个 / 下一个」在编辑器里跳走后，面板高亮必须跟着走，
因此主进程在 `showDiffInEditor` / `stepDiff` 两个 handler 里都会 `send(CHANNELS.activeDiff)` 给面板。

> 这条通道是补上的：最初只在面板侧高亮，编辑器内跳转后面板高亮就停在原地对不上了。

### 跨进程「应用状态」同步（`preview:applied`）

应用有**两个入口**，走哪一个都必须让面板状态与磁盘一致：

| 入口 | 面板是否天然知情 |
|---|---|
| 预览面板自己的「应用」按钮 | 知情（本地标记） |
| 左侧编辑器内联工具条的「应用此变更」 | **不知情** —— 落盘在主进程，面板是另一个渲染进程 |

所以主进程在**落盘成功后**统一广播 `preview:applied`：

- `{ kind: 'applied', collectionId, index, filePath }` —— 面板按 `index` 把条目标「已应用 ✓」；
- `{ kind: 'undone', collectionId, index, filePath }` —— 撤销后把对应条目复位成可应用。

> 快照携带批次与片段身份，撤销只复位对应片段；同文件其他片段保持已应用。旧批次通知不修改当前列表，不能按文件路径批量复位。

### 三向校验的位置没有变

`buildEditorDiff` 构造 payload 时复用 `ReturnPathService.prepareChange`，准备失败不进入预览；应用前再次校验原文、目标存在状态和路径边界，预览后外部变化可能导致应用拒绝。

### 落盘后必须广播（2026-10-03 修复的真实缺陷）

用户实测：「应用后没有及时刷新文件，显示仍然是旧代码，只有关闭文件重新打开才会显示应用后的代码」。

**根因**：落盘发生在**主进程**，而编辑器是**另一个渲染进程**。此前 `applyChange`
返回后**没有任何广播**，编辑器根本不知道磁盘被改写了 —— 只有用户手动关掉文件重开
才会重新读盘。

现在的规则：

| 落盘动作 | 广播 |
|---|---|
| `applyChange` 成功 | `CHANNELS.fileChanged` →编辑器 |
| `undoSave` 成功（撤销也是改写磁盘） | 同上 |

编辑器的 `onFileChanged` 核对目录版本后退出目标的内联标记。普通更新重读已打开标签；创建刷新树并载入真实文件；新增撤销删除则关闭目标标签并刷新树。

> **一条通道只有一个刷新入口**：原先编辑器内点「应用此变更」自己会 `openFile`，
> 现在统一由 `onFileChanged` 驱动 —— 否则应用按钮与最右侧面板两条路径各刷一次，
> 既重复又可能出现先后竞态。

### 全部应用

面板头部有「全部应用」，把本批次里所有可用变更依次写入。

**必须顺序执行，不能并发**：每个变更都要单独做三向校验，而校验基线是
"读文件那一刻的原文"。并发会让两次写入基于同一份基线，后一个可能覆盖前一个的结果。

**单个失败不中断整体**：某个文件校验不过（文件已变、区间非法），其余仍应能应用，
最后统一汇总成功/失败与原因。已应用的条目标成「已应用 ✓」并置灰。

### 采集策略（按可信度依次尝试，共 3 套）

**核心判据从"pre 最多 / 文本最长"改为「文档序最后」** —— 多轮对话里"最新回复"才是这次要应用的目标；
旧判据在历史回复代码块更多时必然选错（曾实际采到旧回复）。

| # | 策略 id | 依据 | 说明 |
|---|---|---|---|
| 1 | `latest-reply-container` | **文档序最后**、且真正含 `<pre>` 的 markdown 容器 | 容器内 `<pre>` 按文档序拼接；`### 文件：` / `### 范围：` 线索**只从该容器**取 |
| 2 | `latest-reply-container-text` | 同上的容器整体 `innerText` | 取不到结构化 `<pre>` 时保留文本形态 |
| 3 | `last-pre-in-document` | 文档序最后一个 `<pre>` | 最后手段，单块场景仍正确 |

**线索只从最新容器取**是关键：历史容器里带 `### 文件：其他路径` 不再干扰。

两个已踩过的坑：
- `[class*="markdown"]` 是**子串匹配**，会同时命中 `<code class="language-markdown">` 与
  `<div class="ds-markdown-title">`；必须按 `tagName` 排除 `PRE`/`CODE`，并**优先选真正含 `<pre>` 的候选**，
  否则会选到最新回复的标题 div 而采到空。
- **外围围栏长度 = 内容内最长连续反引号序列 + 1（最少 4）**，与提示词组装侧 `fenceFor()` 同规则；
  解决"模型用 ````markdown 包住 ```python"时外层被 `splitFences` 截断的问题。
  下限取 4（而非 3）是为了与"程序发出去的片段也用四个反引号"保持一致。

### 消费判定（零注入下的"已消费"）

页面不能被写入（零注入），所以"这条回复已采集过"**只能记在主进程内存**里，用**内容指纹**代替标记：

- **会话标识** = `URL.origin + pathname`（剥掉查询跟踪参数，同一对话稳定）；
- **指纹** = `sha256(采集文本).slice(0,16)`；
- 采集时**原子地**「比对 + 记录」（`ConsumptionStore.consume()`）：
  - 指纹相同 ⇒ `noNewContent`：不解析、不产生待应用条目、**不回退旧内容**；
  - 指纹变化 ⇒ 解析并更新记录。
- **"放弃"与"应用"都算消费** —— 记录发生在采集那一刻，与后续是否落盘无关。

预览面板对 `noNewContent` 有专门文案（"最新回复与上次采集相同，未产生新的待应用变更"），
不再误报成"解析出 0 个代码块"。

### 提示词规范里的围栏约定（请求侧双保险）

**核心原则：输入与输出**共用同一条骨架**（见上文"输入与输出结构统一"）——
模型只需"照抄骨架、只改内容"，不需要推理文件类型或判断含不含围栏行。

| 规则 | 内容 |
|---|---|
| 骨架照抄 | `### 文件：` + `### 范围：` + 围栏；输入输出完全一致 |
| 成对闭合 | 开头四个反引号，结尾必须**同长度**闭合 |
| 四个反引号 | **不是三个**；语言标注按目标文件扩展名给（.md→markdown、.ts→typescript…） |
| 加长规则 | 内容含四个及以上**连续**反引号时，外层比它再多一个 |
| 行号 | **只由 `### 范围` 表达**，围栏内容里绝不写行号 |
| 内层围栏 | 内容里的三反引号（.md 内嵌代码块）**原样保留**，外层四个不会被提前闭合 |

> **为什么不写"语言跟文件类型走"**：用户实测踩过这个坑 —— `.md` 文件里改代码块时，
> "语言跟文件类型走（.md→markdown）"与"含反引号就四反引号"两条规则并列、**没有优先级**，
> 模型只能自己折中、两头不讨好。改成"照抄骨架"后，不需要模型**推理**，规则更少、更不易错。
>
> **为什么删掉旧的"正文不得出现四个反引号"**：它与"固定用四个反引号"直接矛盾，
> 只会让模型困惑；现行规则是"至少四个、必要时加长"。

### few-shot 示例：8 类场景逐一对照（请求侧的"防跑偏"主力）

用户明确要求示例必须**尽可能包含所有情况**（"示例不能太少，一定要尽可能包含所有情况，
这样就可以在提示词内容不规范的前提下也能知道 AI 规范输入输出"）。因此模板把
**8 类场景**逐一写成「【我给你的】→【你该给我的】」对照，每段整段用五反引号包住：

### 已删除：`### 续：` 截断续写约定

早期模板里写过「若内容太长被截断，续写时用 `### 续：<文件名>` 标注」。这条**已删除**，
因为它对解析器**完全无效**：`returnPath.ts` 没有任何 `### 续：` 规则，`续：文件名` 也不是合法路径，
写了只会被当成正文、或让模型以为"可以中途截断"。用户直接问过"截断续写 `### 续：` IDE 能正确提取吗"
—— 答案是不能。

**取而代之**的是明确的分轮约定：

> 每次输出都要把该给的内容给**完整**。若确实太长，宁可**分多轮、每轮给某个文件的完整内容**，
> 也不要在中间截断。

这样把"中间截断"这种**最坏输出**从提示词层面排除掉了（自检 F3f / 离线 X6 锁死）。

⚠️ **模板自身每一段围栏都必须成对**（不能留下没人闭合的 opener）。
这是踩过的真实缺陷：模板是"给模型看的自然语言"，早期在说明里直接写
「.py 用 ` ```python `、.ts 用 ` ```typescript `」，模型把它读成**代码块的开头**，
而说明后面没有配对闭合 → 模型输出出现"有开头没结尾"的代码块。
现在示例整段用**五反引号**包住（示例里必须出现三/四反引号才直观，所以不能再要求"零反引号"），
由单测、自检 F3b 与离线断言 X1 锁死「每段围栏成对」。

注意这只是"请求模型配合"，**不构成正确性依赖**——真正的硬保障是采集侧的围栏自适应（见上）。

#### 用户自定义（分版本）

上面的两套都**不是写死的**：用户可以整段替换任意一版（用户需求原话：
"目前这个系统自带提示词是默认固定的，我希望可以支持用户自行修改系统 prompt"）。

| 项 | 说明 |
|---|---|
| 存哪 | `SettingsStore.customFormatSpecShort` / `customFormatSpecFull` + `customFormatSpecUpdatedAt`（`userData/settings.json`） |
| 怎么生效 | `resolveFormatSpec(customs, variant)`：**当前版本**的自定义非空则原样返回，否则回落 `getFormatSpec(variant)` |
| 隔离性 | 简洁版的自定义**不影响**完整版，反之亦然（这是本轮新增的核心不变量，单测 Z2b 锁死） |
| 消费点 | ① 编辑器「复制提示词」；② File 菜单两种复制 ——**都经 `customSpecsOf()` 取值**，不各处写一遍 |
| 入口 | Settings 菜单「修改提示词…」/ File 菜单同名行 / 编辑器工具栏齿轮，快捷键 `CmdOrCtrl+Shift+P` |
| 面板 | 独立渲染进程（覆盖式浮层），**顶部两个页签**分别编辑两版；预填"当前实际生效的那段"；有未保存标记、字数、实时状态；Esc 关闭、Ctrl+S 保存 |
| 旧数据迁移 | 旧的单字段 `customFormatSpec` 保留为**只读迁移源**：加载时若两版都为空，把它灌给"当前版本"那一格，老用户升级后内容不丢 |

#### 设计取舍

- **只在"复制 prompt"这一侧生效，采集/解析侧不感知**。用户改了输出外观不影响回程解析器 ——
  解析器认的是 `### 文件：` / `### 范围：` 这些**结构线索**，面板文案会明确提示这一点
  （"改动它们之前，先确认模型输出仍满足上面的形式，否则回程无法自动识别"）。
- **空内容 = 回落默认**（双层兜底：`load()` 里空串视同未设置，面板保存时空内容视同恢复默认）。
  这是硬要求：格式段凭空消失会让模型输出无法解析，而且**不会有任何报错**。
- **「恢复默认」是两步**（载入编辑框 → 再点保存），因为一键清库是不可撤销的。
  分版本后载入的是**当前页签那一版**的默认全文。
- **切页签不丢草稿**：`perVariant` 里为每版各存一份 `draft`，来回切不会把未保存的编辑吃掉。
- **`getFormatSpec()` 保持纯粹**（不读设置文件），自定义只从 `resolveFormatSpec` 注入。
  好处：单测不需要准备设置文件，默认模板的不变量（F3b 等）也仍然针对真正的内置文本。
- 提示词的**其余部分**（`## 用户需求` / `## 工作环境` / `## 目录结构` / `## 要改的文件`）
  由程序生成、用户不可改 —— 那是骨架，不是可调项。

自检 Y1–Y15 + 离线验证 `npm run verify:prompt`（27 项，含 Z1–Z4 跑真实的 `resolveFormatSpec`/`buildPrompt`，
以及 **S1–S5 用 stub DOM 真跑 `prompt.js` 与开关逻辑**：验证切页签、草稿保留、保存写对版本、开关启动对齐）。

**采集失败时的诊断**（`DIAGNOSTIC_SCRIPT`）：报告页面标题、可见文本长度、是否含围栏、
以及各候选选择器的命中数，并给出判断（"页面没有代码块" vs "围栏存在但不在 `<pre>` 中"）。
这样选择器过期时能直接看出该补哪套策略，而不是靠猜。

- 从网页**只读采集**回复文本（注入只读脚本读取已渲染消息，不修改页面）。
- diff 预览 UI、一键应用、撤销。
- 用**真实模型回复**校准解析器识别率（P3-5，open）。


## 职责

在"模型输出"与"本地文件"之间建立一条**可解析、可预览、可撤销**的回程链路。

## 核心机制：格式约定由用户驱动，程序只负责解析

"一键同步"成立的前提是输出可解析。但**约定由用户在自己的提示词里提出**，而不是由程序注入指令头。

| 环节 | 由谁完成 | 说明 |
|---|---|---|
| 复制代码、粘贴、写提示词、发送 | **用户**（全部手动） | 程序**完全不参与出程**，见 `human-machine-boundary` |
| 取得格式要求文本 | **程序写剪贴板**（`ui:copy-format-spec`） | 工具栏「复制格式要求」按钮；**只写剪贴板** |
| 把格式要求放进提示词 | **用户**（自己粘贴） | 程序**绝不写入输入框**（零注入边界） |
| 读取回复 | 程序 | 只读；见下文"回程采集方式" |
| 解析输出 | 程序 | 纯本地文本解析，不调用任何模型侧接口，也不去"理解"模型 |
| 确认落盘 | **用户** | 见下文"应用规则" |

因此**不存在任何"注入成本"**——程序不向输入框写入一个字符。

> **为什么不做"程序自动加格式要求"**：那是往输入框写内容，正好踩在项目唯一的硬边界上
> （ADR-0003 零注入）。用户的担心（模型输出格式随意 → 采集不可靠）由三件事共同解决：
> ① 解析器高容忍（四类线索）；② 一键复制格式模板供用户自行粘贴；③ 无法定路径时降级为预览。


## 解析契约（约定）

1. **围栏识别**：以 ` ``` ` 围栏为最外层切分单位，语言标注用于选择语法高亮，不用于决定落盘路径。
2. **路径行**：围栏内首行的特定注释形式声明目标文件（具体语法在实现时冻结并写入本文件）。无路径行的围栏 → 视为"插入当前光标处"，不猜测文件。
3. **多围栏**：一个回复可含多个围栏，逐个映射为待应用变更；无法一一对应路径时**整体降级为预览**，不做半自动落盘。
4. **失败即降级**：解析失败不得静默丢弃，必须把原文完整保留并让用户手动处理；**必须容忍"模型没按约定回复"这一常态**。

## 回程采集方式

| 方式 | 说明 | 定位 |
|---|---|---|
| **只读观察** | 通过 preload 暴露**只读**接口，从网页视图读取消息文本 | 唯一方式。读取不是伪造输入，不产生 `isTrusted: false` 事件，也不修改页面状态 |

**边界**：回程通道**只读**。网页视图不得因此获得任何写入本地文件的能力；本地写入仍由主进程在用户确认后执行。

## 应用规则（信任边界）

1. **默认预览，不默认落盘**（已确认方案 A）：回程结果先以 diff 预览呈现，用户确认后才写入。
2. **写入必须可撤销**：落盘前保留原内容快照；不提供"跳过预览直接覆盖"的静默路径。
3. **路径安全**：目标路径必须通过 `local-file-access` 的白名单校验；越界或不存在的新文件需用户显式确认。
4. **不做自动循环**：解析结果不得自动回注给模型，也不得在回复到达后自动触发发送。

## 与出程边界的关系

出程（代码 → 网页）完全由用户手动完成，**程序不向网页写入任何内容**（见 `human-machine-boundary`）；回程（网页 → 编辑器）是**读取**，不产生输入特征，因此允许由一次人工按键触发解析与应用。二者不冲突。

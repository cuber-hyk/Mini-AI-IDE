# 多项目并行开发：后续议题

记录日期：2026-10-07。本文保存讨论与待验证方向，不是执行计划、已接受的架构决策或当前能力说明。

## 已确认的范围

- 本阶段优化 UI：左侧常驻多项目工作区，中间为官网 AI 对话、输入与本地工具状态，右侧为当前项目目录、文件编辑和 Diff 查看。
- 本阶段不做项目与官网会话的持久绑定，不随项目切换自动恢复官网会话。
- 多项目并行开发留待后续独立调研、规划和实现，不随本次 UI 工作实施。
- 用户希望最终可以切换项目继续开发，而旧项目任务和真实结果仍可保留；“切项目即取消旧项目待回传结果”不能直接作为未来并行模式的产品规则。

## 当前代码事实

- `src/main/index.ts` 创建单一当前项目 FileService、官网 WebContentsView 和工具 integration；目录版本变化调用 tools.reset。
- `src/main/tools/integration.ts` 的 reset 取消自动继续与尚未执行请求，并重置采集及变更状态。
- `src/main/tools/harness.ts` 以当前目录、会话和 generation 校验请求；切换会使剩余请求失去执行资格。已启动命令不因该 reset 立即终止。
- `src/main/tools/processes.ts` 管理 IDE 实例内的进程，查询和停止尚未细分项目归属。
- `src/main/tools/autoContinuation.ts` 以项目目录与会话组成作用域，作用域变化取消待发送。
- `src/main/consumptionStore.ts` 的 sessionKeyOf 使用 URL origin 与 pathname；这不能证明官网会话仍存在。

## 后续候选能力

1. 后台工具并行：各项目独立保留批次、进程、输出、变更记录和编辑状态；前台切换不等于取消任务。预计为中等规模改造。
2. 多 AI 任务持续并行：各任务独立持有官网视图与工具运行上下文，用户自行选择各视图的会话，共享稳定登录分区；不依赖持久保存的会话链接。预计为较大架构改造，尚未选定方案。

待回传结果必须属于原任务。保留结果不等于允许向当前可见网页发送；只有原任务对应页面、会话和批次经核验有效时才有发送资格，否则保留结果并等待用户。

## 独立任务启动前需要决定与验证

- 一项目一运行上下文，还是一项目可包含多个任务；如何管理任务与网页视图生命周期。
- 项目切走后的未保存草稿、授权请求、后台命令和撤销记录如何保留及展示。
- 官网会话被用户切换或删除、登录失效及网页崩溃时，只暂停受影响任务的可行性。
- 后台 WebContentsView 的生成、变化监听、完成识别与限定结果发送是否可靠；多视图的内存和 CPU 成本。
- 多任务修改同一实际文件（含嵌套项目、符号链接和项目外文件）的冲突保护。
- 多项目工具完成时自动复制的归属和覆盖规则，以及全局退出时的进程清理。
- 回归验证：A/B 任务互不串结果、互不中断；没有可靠目标时不发送；切换不丢真实结果；历史请求不重放；关闭任务和退出能完成清理。
- 若接受后台项目自动回传，需通过新的 ADR 明确修改当前“仅当前项目完成事件可回传”的约定，并同步相关能力文档和测试。

本次 UI 效果图只表达前台布局，不表示以上并行能力已实现或已批准具体技术路线。
